# 变更日志

本文件记录 lc-ms-group-advisor 的所有版本变更。

---

## 0.1.0b0 — 2026-09-10

首个版本。

### 新增 — 色谱排序

- 柱型排序键与方向配置化（`COLUMN_TYPES`）：反相 C18/C8/C4 与 HILIC/正相用极性指数，SEC 用分子量
- C4/C8/C18 合并为单一模式——三者同属疏水分配机制，排序方向一致，仅机制不同的柱型单列
- 极性指数由分子式粗估：杂原子加权和 ÷（碳氢骨架 + 不饱和度折减）
- 出峰位置批次内 min-max 归一化到 0–100%（0 = 最先出）

### 新增 — 分组策略

- 百分比阈值模式：组内相邻位置差达到阈值即分出新组
- 质谱能力反推模式：由 cycle 上限反解每组最多化合物数，贪心填充
- 两条硬约束：组内跨度超限、质量不可分辨，触发即强制拆组
- 每个分组边界产出 `split_reasons` 记录（`mass` / `capacity` / `span` / `gap` + 明细），不静默拆组
- 质量冲突记录附带 `pos_gap`（两者出峰位置差），用于区分「可靠时间调度解决」与「共洗脱的不可解冲突」

### 新增 — 质量可分辨判据

- 新建 `mass_resolution.py` 作为唯一判据入口，所有调用点（分组 / 通量 / 核算）统一走 `judge()` / `check_list()`
- 判据 `Δm ≥ k × FWHM`，k 由谷值标准精确反解（二分法），与谷值换算互为严格反函数
- 谷值预设：10% 谷（k = 2.07892，默认，质谱经典定义）、50% 谷（k = 1.41219）、1% 谷（k = 2.76475）、自定义 k
- 判据比较带 1e-9 相对容差，避免浮点导致「Δm 恰好等于判据却判为混峰」
- 峰宽来源三选一：`auto` 跟随设备标称 / `constant` 恒定 Da / `proportional` 按 m/z 等比 ppm；用户实测值优先于标称值
- 谷值定义统一为「相对合成峰的峰顶」，与肉眼所见凹陷一致

### 新增 — 质谱核算

- 设备参数表：QqQ、离子阱、QTRAP（单位分辨，FWHM 0.7 Da）、Q-TOF（高分辨，20 ppm）
- MRM cycle 模型：`T = N₁N₃·dwell + N₁(N₃−1)·delay_q3 + (N₁−1)·max(delay_q1,delay_q3) + overhead`
- 点数计算与双条件判定（点数下限 + dwell 下限），不达标给出「建议每组不超过 N 个化合物」
- 不分组反事实对照：整批化合物的总通道数、cycle、点数、是否会漏检

### 新增 — 质量计算与一致性校验

- 新建 `mass_calc.py`：33 种元素单同位素质量表 + 平均质量表
- 加合物表：阳性 13 项、阴性 7 项，Δ 统一按「离子」口径计入电子得失，可直接与文献 m/z 比对
- 加合物三档判定：唯一命中（化学式与 m/z 互证）/ 多候选（交由使用者选择，不自动挑）/ 零命中（两者至少一个错）
- 容差按设备分流：高分辨走 ppm，标称分辨走 Da
- 严格分子式解析：未知元素直接报错，不做静默跳过；支持嵌套括号与括号后倍数

### 新增 — 配置自检

- `missing_formula`：分子式缺失或非法 → 排序键为占位值，位置不代表真实顺序
- `out_of_domain`：PI 模式下 M > 1500 Da → 极性指数对高分子量无分辨力
- `sec_under_domain`：SEC 模式下 M < 500 Da → 小分子全进孔，几乎没有分离度
- `multi_charge`：母离子 m/z < M − 2 → z > 1，单电荷阈值不适用
- 四类告警全部显式产出，不静默通过

### 新增 — LLM 锚点指针抽取

- 新建 `extractor.py`：LLM 只输出「原文引用 + 槽位」，值由 Python `str.find` 反算并取出
- 双模式：`anchors`（自然语言 / 中小表格）、`columns`（大表格，LLM 只给列语义映射，行由 Python 全量遍历）
- 模式判定由 Python 完成（非空行数与候选分隔符出现次数一致性），零 LLM 调用
- 三条硬闸门：引用必须命中原文、位置必须有序（游标只前进）、编号必须连续；失败回灌缺口清单重试一次，二次失败显式报错
- 槽位必需性分层：化学式缺失阻塞整批、母离子 m/z 缺失告警并明示约束停用、名称缺失自动赋「化合物N」
- 提示词四段式（名词定义 / 正例 / 反例 / 边界例）处理语义噪音，不做算法硬分
- 零信任方案：LLM 输出中不接受任何数值与坐标，幻觉面被物理收窄到「引用是否存在」

### 新增 — 约束解码

- `llm_client` 支持 `response_format` / `json_schema`，在采样阶段禁止协议外输出形状
- 后端不支持时自动降级为仅提示词约束；校验逻辑不依赖其生效

### 新增 — Web UI

- 深色主题单页，三 Tab：分组预测 / 时间参数 / 通量核算
- 分组预测：化合物输入（文本、文件、LLM 抽取、可编辑表格）、色谱与质谱参数、结果区（自检告警、出峰顺序图、顺序表、分组详情含开组原因、质量冲突清单、抽取报告）
- 时间参数：按设备单机模拟 cycle 构成，甘特图逐段展开，各段宽度严格正比于耗时
- 通量核算：离子对逐行录入 + 母离子间 / 子离子间邻近性检查 + 三点判定
- 全部自包含：无外部 CDN、无 emoji、CSS/JS 内联、系统字体

### 新增 — 工程

- `main.py` CLI：`--port` / `--host` / `--pidfile` / `--check` / `--backend` / `--base-url` / `--api-key` / `--model`
- `setup.bat` / `_run.bat`：解释器探测（`py -3.11` 优先，回退 `python`），纯 ASCII 编码 + CRLF 行尾
- `tests/test_mass_calc.py`：质量计算与加合物判定断言
- `tests/test_extractor.py`：抽取协议与三条闸门断言
- Apache-2.0 许可与 NOTICE 归属声明

### 修正 — capacity 模式的位置判据用错几何量，参数与值域脱离配置推动链

**现象（两层）**：

1. `capacity` 模式的分组详情出现「位置差 100% ≥ 阈值 20%」，但界面上找不到任何可设置 20% 的地方，也无从得知该参数存在。
2. 顺该参数追查发现更严重的问题：界面写着「质谱能力反推」，**实际分组结果由位置判据决定**。默认参数下容量上限反推出每组 9 个化合物，而位置判据在 1–20% 区间内每次都先拆组——实测 4 个化合物时容量拆组 0 次、位置拆组 1–3 次；16 个化合物要上限 ≥ 50% 才轮到容量生效。整条滑杆 1–100 里只有 30–100 这一小段容得下容量反推。

**根因（两层）**：

1. **判据用错了几何量。** `capacity` 模式的兜底判据原本复用了 `threshold` 模式的「相邻位置差」，但相邻差是**局部量**（逐对比较，任一相邻对超限即切）；`capacity` 要表达的是「这个采集窗口铺太宽」，是**整体量**。局部量容得下「两端各站一个、中间空着」的组——实测同一批数据（位置 `[0, 22.8, 72.2, 73.3, 74.2, 83.5, 88, 100]`，全批跨度 100%），相邻差上限 50% 判定所有相邻对均合格，给出 1 组。两个语义不同的判据还共用了同一个滑杆模板，`min="1"` 一并被照抄——一个以 100 为满量程的量配了 1–20 的取值范围，看似有范围，实则把兜底判据变成了主判据。
2. **参数与值域都没进配置推动链。** `max_gap_pct` 只以函数签名默认值 `20.0` 的形式存在，`run_separation` 的参数表里没有它；`DEFAULT_CONFIG.params` 自身还缺 5 个键（`fhsw_mode` / `fhsw_da` / `fhsw_ppm` / `valley_preset` / `k_custom`）。源头残缺，下游只能各自就地写字面量兜底。滑杆的 `min` / `max` / `step` 更是完全没进这条链，界面里手写了两份（`1–20` 与 `1–100`）。

**修复**：

- **判据换对象**：`group_by_capacity` 的兜底判据从「相邻差 > 上限」改为「组内首尾跨度 > 上限」，拆组原因记作 `span`（`threshold` 模式的 `gap` 不变）。跨度 = 候选化合物位置 − 该组首个化合物位置
- **参数改名**：`max_gap_pct` → `max_span_pct`，标签「位置差上限(%)」→「组内跨度上限(%)」。语义已变，**不做旧名兼容读取**——旧配置文件里的 `max_gap_pct` 会被忽略，不与新键混用（该键仍会随旧配置原样保留在 `get_all()` 输出中，但无任何代码读取）
- **值域有依据**：位置经批次内 min-max 归一化，全批跨度恒为 100%，一组是批次的子集，故上限天然落在 (0, 100]；默认 **100 = 不干预**，分组完全由容量与质量判据决定，与「质谱能力反推」名实相符
- **新增 `span_critical_pct` 回显**：以「无跨度约束」跑一次分组，取各组实际跨度的最大值，即「完全不触发跨度判据所需的最小上限」。不用 `100×(c-1)/(N-1)` 一类均匀分布解析估计——真实峰位是聚集的，估计偏乐观（16 化合物、容量 9：解析估计 53.3%，实测需 68.5%）。上限低于该临界值时，分组详情显式告警
- **配置推动链收口**：`config_manager` 新增 `PARAM_SPEC`（每项的 `kind` / `default` / `min` / `max` / `step` / `label` / `help`），`DEFAULT_CONFIG.params` 由它派生；`default_param()` 与新增的 `param_spec()` 同源；`/api/config` 随配置下发 `param_spec`
- **界面值域不再手写**：滑杆的 `min` / `max` / `step` 全部移除，改由 `applyParamSpec()` 从 `param_spec` 注入；缺省值兜底也从 `|| 5` 一类字面量改为回落 `SPEC[key].default`。HTML 里只剩「控件 id ↔ params 键」的结构映射，不再是值的第二份拷贝
- 界面文案按判据对象分别撰写：`threshold` 标注为「分组定义本身」，`capacity` 标注为「兜底判据」并说明 100 = 不干预

**验证**：

- `/api/config` 下发 `param_spec`；`params.max_span_pct` = 100，旧名 `max_gap_pct` 零残留
- 跨度判据行为：8 个化合物（容量上限 9）临界 100%——设 99.5% 时跨度拆 1 次、设 100% 归零；16 个化合物临界 68.5%——设 68.0% 时跨度拆 1 次、设 68.5% 归零
- `threshold` 模式不受影响：拆组原因仍为 `gap` / `op=>=` / 阈值 5.0，`max_span_pct` 与 `span_critical_pct` 均回显 `null`
- 界面新元素齐全（`span-cap-row` / `max-span-pct` / `max-span-val`），旧元素零残留，内联 JS 通过 `node --check`
- 回归：`tests/test_mass_calc.py` 25 PASS / 0 FAIL，`tests/test_extractor.py` 59 PASS / 0 FAIL，`separator` 模块自测正常

### 修正 — 三个页面各持一份同名参数的值，取值域手写在 HTML

**现象**：分组预测 / 时间参数 / 通量核算三页各有一组 dwell、峰宽、点数下限、Q1、Q3 切换延迟、额外开销控件，键名相同却互不相干——在时间参数页调 dwell，分组预测页反推容量时用的还是另一个值；两处的取值范围也各写一份（时间参数页 dwell 下限 2 ms，分组预测页 1 ms）。通量核算页另有第三份。此外时间参数页根本没有「额外开销」控件，可 `T_cycle` 公式里一直带着它。

**根因**：界面取值域没有单一来源。数值控件只有分组预测页那一组挂在配置推动链上；时间参数页与通量核算页的同类控件是各自手写的第二、第三份拷贝，`min` / `max` / `step` / `value` 全写在 HTML 里。同一个物理量被当成三个互不相关的输入，改一处不会传播到另外两处。

**修复**：

- `config_manager` 新增 `TIME_SPEC`（时间参数页专用输入：N₁ / 推斥频率 / 叠加次数 / 扫描范围 / 扫描速率 / 填充时间 / 模式切换），与 `PARAM_SPEC` 组成 `PARAM_SPEC_ALL`；`default_param()` 与 `param_spec()` 同源取该总表。是否持久化的区别只体现在 `DEFAULT_CONFIG.params` 仅由 `PARAM_SPEC` 派生——两张表的取值域都归一处管
- 前端新增 `CTRL_SPEC`（控件 id → 参数键），把三页的数值控件登记进同一张表：`dwell_ms` / `delay_q1_ms` / `delay_q3_ms` 各对应 4 个控件，`peak_width_s` / `n_min` / `overhead_ms` 各 3 个。任一控件改动即同步其余并写回 `config.json`（`mirrorParam`）；时间参数页专用键不在配置里，只同步不落盘
- 质量分辨率那组（FWHM / k 系数）原本已由 `mirrorRes` 在 grp ↔ flux 之间同步，单独列入 `SPEC_INJECT_ONLY`：只注入取值域，不重复接管同步，避免两个机制各写一次且先后顺序不定
- 时间参数页 QqQ 面板补上「额外开销(ms)」控件（原公式含该项却无输入入口，恒取配置值）
- 所有参数控件的 `min` / `max` / `step` / `value` 从 HTML 移除，改由 `applyParamSpec()` 注入取值域、`loadConfig()` 统一回填初值（配置里有该键则用配置值，没有则回落 `SPEC` 默认值）
- 切页时重算本页结果（`initTabs`）：参数跨页共享，在别页改过之后本页的旧数字已经过期
- QTRAP 面板的 N₁ 上限由 60 统一为 100——与 QqQ 是同一个物理量（一个 cycle 里采集的母离子数），没有理由各持一套范围

**验证**：

- `/api/config` 下发 24 项 `param_spec`（17 项持久化 + 7 项时间参数页专用）；后者不进入 `params`，不落盘
- 登记控件 37 个（参与同步）+ 6 个（仅注入取值域），全部存在于页面；页面参数控件零未登记
- 时间模拟 `overhead_ms` 取 2 / 10 / 50 时 `T_cycle` 依次为 880.0 / 888.0 / 928.0 ms，增量恒等于开销之差
- 四台设备时间模拟与设备标注复核通过：QqQ、四极杆-飞行时间 Q-TOF（实验性）、（线性）离子阱（实验性）、Q离子阱 QTRAP（实验性）
- 参数控件的 `min` / `max` / `step` / `value` 残留数为 0（动态生成的离子对表格行除外）
- 内联 JS 通过 `node --check`

### 修正 — 设备标注

- 设备支持度分档：`DEVICES` 中仅 `qqq`（三重四极杆 QqQ）为正式支持，`it`（线性离子阱）、`qtrap`（Q离子阱 QTRAP）、`qtof`（四极杆-飞行时间 Q-TOF）的显示名统一加「（实验性）」后缀
- 后缀写在 label 上，随 label 自然传播到全部展示面：设备下拉框（分组预测 / 通量核算）、核算结果 `device`、时间参数页 `device_label`，不会出现只在某一处标注的情况
- 计算路径零改动：cycle 公式、点数下限判定、质量可分辨判据对四台设备共用同一套代码，不做 label 或设备身份分支；「实验性」只指该设备的标称参数与界面标注未经充分实测验证，不降低也不改变任何计算结果
- 消除设备名重复定义：`web_ui.TIME_DEVICES` 改为从 `DEVICES` 派生（原为第二份手写设备名，是标签/参数的漂移点）

### 修正

- **MRM cycle 公式跨母离子边界的计时代价**：原模型跨母离子边界只计 `delay_q1`，未考虑 Q3 也在并行动作。当 `delay_q3 > delay_q1` 时该模型系统性低估 cycle。改为取 `max(delay_q1, delay_q3)`，五处同源公式同步修改（`separator.max_compounds_per_group`、`ms_engine.evaluate_group`、`ms_engine.evaluate_all`、时间参数页 QqQ / QTRAP 模拟、通量核算），并修正 `max_c` 反推的 off-by-one 与清理死代码
- **子离子通道数语义**：时间参数页原将 N₃ 当作「总通道数」，并按 `N3 // N1` 整数除法反推每个化合物的通道数，在 N₁=20 / N₃=45 时静默丢弃 5 个通道。修正为「每个母离子的子离子通道数」，总通道数 = N₁×N₃
- **质量分辨率判据系数**：原实现取 k = 1，对应谷值 94%（凹陷仅占峰高 6%，肉眼完全看不出是两个峰），比经典定义宽松一倍以上，导致标称分辨下系统性漏报混峰。改为按谷值标准精确反解，默认 10% 谷（k = 2.07892）
- **`mass_resolution.py` 模块文档中的判据系数写错**：文档表格给出的「精确解」k 值与实现算出的实际值不符（50% 谷写作 1.41239 / 实际 1.41219，10% 谷写作 2.07914 / 实际 2.07892，1% 谷写作 2.76477 / 实际 2.76475），闭式近似一列也有末位偏差，且「50% 锚点相差 0.13%」的表述不准确。经 60 位精度独立复核确认**实现正确、文档错误**，已按实现输出修正文档数值（50% 锚点实际相差 0.14%，10% / 1% 锚点小于 0.001%）。实现代码未改动
- **质量可分辨未纳入分组硬约束**：原实现只在事后报告，不参与分组决策，可产出物理上不成立的合并方案。改为两种分组模式的硬约束，冲突即强制拆组
- **甘特图渲染不完整**：省略段的毫秒值被置 0 且渲染时过滤宽度过小的段，导致图形只覆盖可见部分（QTRAP 更因缺少省略段而只显示约 30% 宽度）。改为省略段按剩余化合物的真实耗时聚合计宽、移除宽度过滤，使各段合计恒等于 cycle
- **甘特图 tooltip 被裁切**：容器 `overflow: hidden` 导致首尾段提示浮层被截断。改为容器不裁剪 + 首尾段单独补圆角 + 悬浮段提升层级
- **缺化学式静默取极性 0**：`polarity_index(formula) if formula else 0.0` 使缺分子式的化合物静默获得 PI=0，被排入「非极性/纯烃」档，界面上看不出异常。改为返回 None 并由自检转成显式告警
- **母离子缺失时质量约束静默失效**：`_mass_conflicts` 遇空母离子直接返回空列表，导致质量约束恒不生效而界面仍显示可分辨。改为告警并明示约束未启用
- **LLM 抽取静默丢弃条目**：名称为空的化合物被 `continue` 静默跳过、m/z 转换失败被静默置 None。改为统一走抽取报告，缺失与失败逐条列出
- **前端按名称映射分组**：重名化合物会串组，改为按输入原始序号 `idx` 映射
- **`_parse_part` 括号倍数外溢**：`Fe(C2H3O2)3` 被解析为 `C6H9Fe3O6`（Fe 也被乘 3），根因是括号组并入父组后整体缩放。改用递归下降，倍数只作用于括号内部
- **Windows 启动脚本被破坏**：批处理文件在重写后丢失 CRLF 行尾（变为裸 LF）且混入非 ASCII 中文，`goto` / `:label` / 多行 `if` 块在裸 LF 下解析错乱、GBK 按 UTF-8 解码产生乱码并可能吞掉后随引号。修正为强制 CRLF 写入 + 纯 ASCII 编码 + 解释器探测式选择
- **`_run.bat` 硬编码本机绝对路径**：启动脚本内写死含用户名的 Python 解释器路径，违反对外交付物的脱敏要求。改为走 PATH 的解释器探测
