> 版本：v0.1.0-plan（草案，待拍板）
> 作者：wUwproject | 许可证：Apache 2.0
> 依赖来源：`douyin_podcast_maker`（成熟资产移植）+ `maby_agent` 智能体范式

## 〇、结论先行

在 `podcast-maker/` 建一个**本地单页 Web 智能体**，把现有播客生产线从"手工写脚本 + 硬编码清单驱动"升级为"配置驱动 + LLM 生成 + 硬门禁校验"。

- **形态**：完全对齐 `maby_agent/lc-ms-group-advisor` 范式——`main.py` 入口 + `setup.bat` 一键起 + `config_manager` 参数总表 + `llm_client` 多后端 + 深色自包含单页 + README/PROTOCOL/CHANGELOG/llms.txt 四件套。
- **规模**：约 12 个模块、4500 行量级（与 lc-ms 的 4580 行同量级）。
- **核心增量**：时长/语速的**实测校准闭环**、脚本生成的**硬门禁**、音频参数的**物理可行性校验**、字幕断行的**禁则算法**。
- **顺带修复**：现有项目 7 个已污染产物的缺陷，迁移时一次修掉、不回填旧集。

三处不走原路的地方先说清楚：

1. 原 `script_generator` 用 OpenAI SDK（引入 pip 依赖）→ 改为标准库 `urllib` 直连 OpenAI 兼容 API，与 lc-ms 的 `llm_client` 一致。
2. 原"自动化"从未真正跑通（13 期全是手写脚本）→ 新项目以 LLM 生成脚本为**默认路径**，手动编辑为兜底。
3. 原产物无校验 → 新项目合成完成即产出**校验报告**，不通过不给产物。

## 一、定位与边界

### 1.1 它是什么

一条**从素材到成片**的播客生产线，四种输入都能吃：

| 输入 | 处理 |
|---|---|
| 直接粘贴文本 | 作为素材 |
| 上传文件（.md / .txt / .docx / .pdf） | 抽取为纯文本 |
| 书稿 + 章节锚点 | 按锚点切出目标章节（不按行号） |
| 只给主题 | LLM 从零起稿（需显式开启） |

五种输出：

| 产物 | 规格 |
|---|---|
| `final.mp4` | 横屏（默认 1920×1080，可改） |
| `final_v.mp4` | 竖屏（默认 1080×1920，可改） |
| `podcast.mp3` | 音频（采样率/码率/声道可配且经可行性校验） |
| `cover_*.png` | 封面三版（16:9 / 3:4 / 1:1） |
| `article.md` | 公众号图文（对话体，由 LLM 生成而非转录） |

### 1.2 它不是什么

| 不做 | 原因 |
|---|---|
| 不做真人语音克隆 | 音色限定在引擎自带音色（本地 Qwen3-TTS 九个 + Edge-TTS 内置），不引入未授权的声纹克隆 |
| 不做 AI 生成主持人形象 | "人物"仅做**说话人指示**（色块/字母/用户自备立绘），不生成人脸 |
| 不做视频剪辑 | 不做转场、特效、多机位，形态限定在"固定背景 + 字幕 + 轻动画" |
| 不做平台发布 | 只出产物，上传到各平台是外部动作 |
| 不做 BGM 曲库 | BGM 只提供"Python 合成 pad"与"用户自备文件"两条路 |

### 1.3 三条设计原则（承自 lc-ms 范式）

1. **不静默**——配置矛盾一律显式报错或告警：码率超出采样率上限、字体族名不存在、时长偏差超阈值、脚本同一人连说超限，全部拦下。
2. **不做假功能**——没实现的能力不摆到界面上。emotion 字段若无人消费，就不放进脚本协议；一旦放进，TTS 与渲染必须真的读它。
3. **LLM 只做它擅长的**——写台词、做风格改写交给 LLM；字数统计、时长换算、断行、编码参数全部由 Python 确定性完成，**LLM 不输出任何数字**。

## 四、需求映射

### 4.1 需求一：音频帧率 / 视频帧率

**先厘清术语**：视频的"帧率"是 fps；音频没有帧率，对应的是**采样率**（Hz）。方案里两者都开放为配置项，并把音频的完整参数面暴露出来。

| 组 | 参数 | 默认 | 取值范围 | 说明 |
|---|---|---|---|---|
| 视频 | `video.fps` | 30 | 24 / 25 / 30 / 50 / 60 | 帧率 |
| 音频 | `audio.sample_rate` | 44100 | 16000 / 22050 / 24000 / 32000 / 44100 / 48000 | 采样率 |
| 音频 | `audio.bitrate_kbps` | 192 | 64–320 | 码率 |
| 音频 | `audio.channels` | 1 | 1 / 2 | 声道（播客建议单声道） |
| 音频 | `audio.codec` | `libmp3lame` | mp3 / aac | 音频编码 |

**关键：采样率与码率存在物理约束，必须校验而不是静默钳制。**

MP3 的码率上限由采样率所属的 MPEG 版本决定：

| 采样率 | MPEG 版本 | Layer III 码率上限 |
|---|---|---|
| 32000 / 44100 / 48000 | MPEG-1 | 320 kbps |
| 16000 / 22050 / 24000 | MPEG-2 LSF | **160 kbps** |
| 8000 / 11025 / 12000 | MPEG-2.5 | 64 kbps |

这正是原项目"配置写 192k、实测 160k"的根因——22050 属 MPEG-2 LSF，192 kbps 在此采样率下不存在，ffmpeg 静默降级。新项目的处理：

- `audio_engine.validate_params()` 是**唯一校验入口**，前端提交即校验、后端执行前再校验一次。
- 组合不可达 → 返回 `ok:false` + 明确原因（"22050 Hz 属 MPEG-2 LSF，码率上限 160 kbps，请改采样率或码率"），**不自动改数**。
- 界面在采样率切换时，码率滑杆的 `max` 随动收紧（值域来自参数总表，不在页面另写一份）。
- 修复后默认值取 44100 Hz / 192 kbps，组合可达。

**视频编码参数**一并开放：`preset`（medium 默认）、`crf`（20 默认）、`pix_fmt`（yuv420p）、横竖屏尺寸。

### 4.2 需求二：A/B 角音色

现有 `edge_voice_a` / `edge_voice_b` 是硬编码字符串，方案升级为**音色注册表**：

| 能力 | 实现 |
|---|---|
| 动态音色列表 | 启动时调 `edge-tts` 语音列表接口，过滤 `zh-*`，缓存到 `config.json`，附手动刷新 |
| 音色元数据 | 性别、地区（大陆/港台）、风格标签（新闻/温柔/活泼/方言），供筛选 |
| 试听 | `POST /api/tts/preview`，用固定样例句合成 3 秒 wav，返回 base64 给 `<audio>` 播 |
| 角色定义 | A/B 各自绑定：音色 + 语速 + 称谓 + 颜色（说话人指示用） |
| 音色互换 | 一键交换 A/B 全部绑定 |
| 引擎切换 | `edge`（备选，LGPL-3.0）/ `qwen3tts`（默认，Apache-2.0）；音色列表随引擎切换，两套音色键各自存值、界面只露当前引擎那一套 |

> **后续演进（2026-09-13）**：本地引擎已由 CosyVoice 换为 **Qwen3-TTS**（键名
> `qwen3tts`，音色改由 `tts_service/serve.py` 的 `/speakers` 枚举），`edge` 转为备选。
> 两套音色键以 `engine_scope` 声明归属，界面按当前引擎只显示对应那套——同屏不再并列四个「A 角音色」。
> 本节下方两条算法修正（采样率不硬编码、变速走 atempo）在新路径上同样成立。

**CosyVoice 路径的两个原算法 bug 必须修掉**（否则两条路径语义不等价）：

| 原问题 | 根因 | 修法 |
|---|---|---|
| 输出采样率硬编码 22050 | CosyVoice2 实际输出 24 kHz | 从服务响应头/配置读取，不写死；写入前重采样到目标采样率 |
| `_change_speed` 用 `np.interp` 重采样 | 重采样 = 变速**且变调**；而 edge 侧 `rate` 是变速**不变调** | 改用 `ffmpeg atempo`（保持音高），两条路径的 `speed` 语义对齐 |

**A/B 语速独立**：`speed_a` / `speed_b` 各自配置，默认 1.0。`duration_model` 按句分别用对应语速换算。

### 4.3 需求三：时长、语速，与"字/时间"显性化（核心）

这是整个方案里技术含量最高的一块，直接针对原项目"脚本估值比实测高 18–27%"的系统偏差。

#### 4.3.1 单一入口

所有"字数 ↔ 时长"换算**只能**经由 `duration_model.py`，禁止在调用点另写系数（对齐 lc-ms "所有质量判定必须经由 `mass_resolution.py`"的纪律）。

| 函数 | 用途 |
|---|---|
| `estimate_seconds(text, speaker, cfg)` | 单句估时 |
| `estimate_total(script, cfg)` | 全篇估时 |
| `chars_for_target(seconds, speed)` | 由目标时长反推目标字数 |
| `calibrate(pairs, cfg)` | 由实测音频回填校准系数 |
| `explain(script, cfg)` | 产出逐句明细，供界面显性展示 |

#### 4.3.2 估时模型

**L1 单参数（默认，样本 < 20 句）**

$$\text{eff} = N_{\text{汉字}} + 0.5\,N_{\text{标点}}, \qquad t = \frac{\text{eff}}{k \cdot s}$$

`s` 为该句说话人的语速倍数，`k` 为**标准语速**（有效字/秒 @ s=1.0），当前值 **4.39**
（= 256 汉字/分钟 × 1.029 折算）。脚本阶段一律用它，与音色无关——稿子的时长目标不随
「这一期换了哪个音色」变。锚点：国家语委《普通话水平测试实施纲要》正常语速 240 音节/分钟、
朗读/播音口径 250–270 字/分钟、本机 391 句实测 256 汉字/分钟，取实测那一档。

**L2 三参数最小二乘（样本 ≥ 20 句自动启用）**

$$t = a\cdot N_{\text{汉字}} + b\cdot N_{\text{标点}} + c$$

用正规方程解 3×3 线性系统（手写高斯消元，不引入 numpy）。`c` 吸收句首句尾的固定静音开销。标点计停顿——这是原模型完全忽略的一维。

#### 4.3.3 校准闭环

```
合成完成 → 逐句实测音频时长 → 与字数配对
        → calibrate() 拟合/更新 k 或 (a,b,c)
        → EMA 平滑（alpha=0.3）写回 config.json
        → 下一集用新系数
```

- 校准样本按**音色 + 语速**分组存储，不同音色的语速不同不互相污染。
- 校准数据只累积不清零，每条记录含时间戳、引擎、音色、句长、实测秒数。
- 校准的出口是**比例**：`音色语速 ÷ 标准语速`，显示在配置页每个音色下拉框下面
  （如「比例 0.91 … 比标准慢 · 实测 171 句」），没有实测就照实写「尚无实测」。
  脚本估算不再读它——估时只有标准语速一把尺子；比例回答的是另一个问题：
  「这一期换了这个音色，成品会比脚本估的长还是短」。

#### 4.3.4 显性化的三处呈现

**（1）事前反推**——输入目标时长与语速，立刻给出目标字数：

```
目标 4 分 00 秒 @ 语速 1.00x   →   目标有效字数约 1200 字（含标点约 1420 字）
若语速调到 1.15x              →   目标有效字数约 1380 字
```

**（2）事中实时**——脚本编辑区顶部常驻仪表盘，随每次编辑刷新：

```
当前字数  1247 / 目标 1200 字        +3.9%
预估时长  4 分 09 秒 / 目标 4 分 00 秒   +3.8%
逐句明细  最长的 3 句：B#12 42字/13.8秒  A#27 40字/13.1秒  B#31 38字/12.5秒
```

**（3）事后实测**——合成完成显示对照表：

| 指标 | 预估 | 实测 | 偏差 |
|---|---|---|---|
| 总时长 | 4:09 | 4:06 | −1.2% |
| 有效字/秒 | 4.87 | 5.02 | +3.1% |
| 最长句 | 13.8 s | 13.2 s | −4.3% |

偏差超阈值（默认 8%）→ 界面顶部告警，并把偏差量作为反馈项回灌 LLM 重生成一次。

### 4.4 需求四：输入文件/内容 → 按倾向写 JSON（完全调用 LLM）

#### 4.4.1 素材摄入 `ingest.py`

| 来源 | 处理 | 依赖 |
|---|---|---|
| 粘贴文本 | 直通 | 无 |
| `.md` / `.txt` | UTF-8 读取，剥离 Markdown 语法 | 标准库 |
| `.docx` | 解压 `word/document.xml` 抽文本 | 标准库 `zipfile` + `xml` |
| `.pdf` | `pdftotext` 若可用，否则显式报错 | 外部命令（缺失时明确提示，不静默返回空） |
| 书稿 + 锚点 | 按 `## 标题` 锚点切章 | 标准库 |

**书稿切章不再用行号**。原 `book_plan.yaml` 用静态行号定位，书稿动一个字就整体错位，且 `extractor` 用 `min(end, len)` 静默截断。新方案：

- 切章靠**锚点匹配**（章节标题文本），匹配不到 → 显式报错并列出候选标题，绝不截断。
- 每期的来源记录写成 `source_ref.json`（书名 + 锚点 + 抽出的字符数 + 内容哈希），书稿更新后可检测"本章节是否变过"。

#### 4.4.2 脚本生成 `script_engine.py`

**完全调用 LLM**，且 LLM 只输出它擅长的东西：

| 交给 LLM | 交给 Python |
|---|---|
| 台词文本、A/B 分工、话题展开、口语化改写 | 字数统计、时长估算、同一人连续句数校验、句长校验、JSON 结构校验 |
| 情绪标签（在受控词表内选） | 标签合法性校验 |
| 无 | 任何数字（`estimated_seconds` 由 Python 算，**不采信 LLM 的返回值**） |

**倾向（style_profile）做成结构化维度**，而不是一句自由文本：

| 维度 | 取值 | 对 prompt 的作用 |
|---|---|---|
| 体裁 | 论证型 / 故事型 / 科普型 / 对辩型 / 复盘型 | 决定句式与展开路径 |
| 情绪密度 | 低 / 中 / 高 | 控制情绪标签比例与感叹词 |
| 提问频率 | 低 / 中 / 高 | 控制 A 抛问题的密度 |
| 比喻密度 | 低 / 中 / 高 | 控制类比用量 |
| 互动词强度 | 克制 / 自然 / 热络 | 控制"对吧""你想想"类口头禅 |
| 称呼 | 自定义 | A/B 互相怎么称呼 |
| 禁用词 | 列表 | 硬约束，生成后扫描 |
| 额外要求 | 自由文本 | 补充说明 |

六套**预设**（论证/故事/科普/对辩/复盘/自定义），可保存为新预设 —— 对齐 Orchestrator 的模板管理（新建/保存/覆盖/刷新）。

**门禁**（形式项在生成阶段判完，不过就定点修补——只把点名的句子交给模型改，全篇行数
一个字不动；轮数取 `script.max_llm_rounds`；修满轮次仍不过，就把这一版稿子连同门禁结论
一起落盘，脚本阶段到此为止——合成端不再重判，
只在出片前提醒一次，由人决定改稿还是照出。
其中总时长偏差是**软门禁**——判的是估算值，不达标只在报告与界面上标「提示·不阻断」，
既不拦放行也不回灌重写：真章要等合成出来才算，口径本身也只是个通用语速，拿它把稿子
打回去重写，等于让模型围着一个它既测不出、也控不住的秒数反复改）：

| # | 检查 | 判据 | 不过的处理 |
|---|---|---|---|
| 1 | JSON 合法 | 可解析为数组 | 结构坏了，只能整篇重出 |
| 2 | 字段完整 | `speaker`/`text`/`emotion` 齐备 | 结构坏了，只能整篇重出 |
| 3 | 同一人连续句数 | 同一人连着说的句数 ≤ 对话形式给的上限（A / B 各一条） | 代码压连续句（`enforce_max_run`），不交给模型 |
| 4 | 句长 | 8–40 字 | 定点修补（逐句给句号、字数与改法；**不许拆句并句**） |
| 5 | 单句时长 | ≤ 15 秒 | 定点修补（点名超时的句号） |
| 6 | 总时长偏差 | ≤ 15% | **不回灌**：软门禁，记「提示·不阻断」 |
| 7 | 情绪标签 | 在受控词表内 | Python 就近归并，记 WARN |
| 8 | 禁用词 | 未出现 | 定点修补（逐句给命中词与替换落点，明示只改这几句） |
| 9 | 片头/片尾 | 首句为统一报幕、末句为统一告别（**但不在稿子里判**） | 代码在**整期定稿那一刻**粘上（`glue_intro_outro`）：只加不改、正文零损失；模型不写这两句，也就没有判据可设 |
| 10 | 四项内容禁令 | 扫描通过 | 定点修补 |

第 10 项的"四项内容禁令"承自 `PODCAST_SPEC.md` 第四章，做成**可配置的规则表**（正则 + 关键词），不写死在代码里。

**编辑能力**：生成的脚本在界面上是可编辑表格——逐句显示序号、说话人（可切换）、台词（可改）、情绪、字数、预估秒数、实测秒数（合成后回填）。改任意一处，仪表盘与门禁状态实时重算。

#### 4.5.4 字幕 `subtitle_engine`

**核心修复：断行算法**。原 `_wrap()` 逐字符硬切，实测 393 处折行中 42 处（11%）断在词中间（`智|能体`、`不该停|的地方`）。

新算法（四级，唯一入口，视频与字幕共用）：

1. **token 保护**：先用正则切出不可分割单元（英文词、数字、`GPT-4` 类连字符词、URL），不在 token 内部断。
2. **标点优先**：优先在 `，。！？；：、` 之后断行；若有多个候选，取最接近行长上限者。
3. **禁则校验**：断点前后不得违反中文避头尾规则——
   - 行首禁则字：`的了是在和与就都也还而且所因为以把被让给对从到个之其能会要可这那` 等不作行首；
   - 行末禁则字：`一第` 等量词/序数前缀不作行末；
   - 标点不作行首。
4. **兜底**：无合法断点时按二分回退到最近的合法位置；实在无解则硬切，**但记入校验报告的 WARN**，不再无声无息。

**版式两档**——差别只剩**一个轴**（双行档已删除，v0.42.0）：

| 档 | 轴 | 折行 | 定位 |
|---|---|---|---|
| 单行滚动 | 横 | 不折，一句一行原样进窗口 | 装得下就静止居中；装不下就走三段式横滚（见下） |
| 歌词 | 纵 | **行数自己算**（`wrap_balanced`：每行容量先算出**下界**，每刀在合法断点里取最接近均分的那个；「不许切词」是硬约束，均衡是偏好，行数允许比下界多一行） | 每句单独算位置 + 换句整块 `\move` 上滚（**默认**） |

**只有一个框，两档共用**：不是 per-line 填充块，而是**一个固定宽高的半透明矩形**（`\p1` 绘图事件，垫在图层 0）：左 = `margin_lr`、右 = 画幅宽 − `margin_lr`、底 = 画幅高 − `margin_v`（竖屏取 `margin_v_vertical`）、高 = **框行数 × 行距**（单行档 1 行、歌词档 `subtitle.frame_rows` 行，同一个算式代入不同行数）。文字用 `\clip` 裁到框内，描边宽取 `subtitle.outline`（**两档共用**，见 `frame_geometry`）。所以边距/底色/描边这批点位**只剩一套语义**：管「框」——从前单双行拿它们管「文字距边 + 填充块」，同一批键在两种模式下意思不同。

**单行滚动的三段式**：位移只等于「文字宽 − 框宽」（滚的是溢出那一截，不是整句），速度 = 文字宽 ÷ 句时长（等于语速），于是

```text
① 句首静止：文字左缘贴框左     时长 = 句时长 × 框宽 ÷ 文字宽
② 匀速左移：位移 D = 文字宽 − 框宽
③ 句尾静止：文字右缘贴框右
```

滚动时长 = 句时长 × D ÷ 文字宽 **恒小于句时长**——任何长度的句子都滚得完，不需要容差也不需要兜底分支；句首静止约 9.8 秒（横屏默认值），与句子长短无关。整句一个字不丢（旧单行档是裁掉超出框口的那截：104 字那句实渲只剩中间约 33 字）。文字宽按实渲标定的系数算（汉字 0.751 / 全角 0.820 / 半角 0.438 × 字号），**不是**「一个汉字一个字号」——按后者估会宽出三成，终点就跑过框。

**歌词档**：三句窗口（可见句数、框行数、上滚时长三个参数），当前句在**框的垂直中心**、其余按顺序排开；**上限按行计（含空行）**，每句代价 = 1 个空行 + 自己折的行数，放不下的句子在换点处上滚淡出。实测 libass **不会**自动折行（不写 `\N` 的长句直接顶到画面边），所以「换行自动」这事只能自己算——这一档就是照左右边距与字号把行数算准。**断词率只在这一档判**：单行滚动档不折行，没有断点，统计按轴返回（`wrap_stats(..., axis)`）而不是靠「行数上限 = 1 就跳过」这种巧合。

**高亮**（开关 + 一个配色）：当前台词染成高亮色，盖过说话人的本色。歌词档染「正在读的那一句」，非当前句走本色并压暗（A/B 默认是纯白，比金色更亮，不压暗就成了「高亮那句反而更暗」）；单行滚动档同屏只有一句，开高亮等于整句换色。

**其它字幕能力**：字号（横/竖分开）、左右与底部边距、描边宽度、背景框透明度。

**字体修复**：原代码把**文件路径**填进 ASS 的 `Fontname`（字体族名）字段，导致 libass 找不到而回退系统字体。新方案：

- 建立字体表：内置一份 SIL OFL 字体（随包分发）+ 探测系统字体（`Microsoft YaHei` / `SimHei` 等）；
- ASS 的 `Fontname` 填**真实族名**，字体文件通过 ffmpeg `ass=sub.ass:fontsdir=<目录>` 指定；
- 选定字体在当前环境不可用时，界面显式报错，不静默回退。

## 六、迁移时一并修复的 7 个原缺陷

全部来自对现有 13 期产物的实测，不回填旧集、只保证新集正确。

| # | 缺陷（实测证据） | 根因 | 本项目修法 | 校验方式 |
|---|---|---|---|---|
| 1 | 字幕断词 11%（`智\|能体`） | 逐字符硬切 | 四级断行算法（token→标点→禁则→回退） | 断词率必须为 0，进校验报告 |
| 2 | 音画差 2.52 s（video 243.00 vs audio 240.48） | `-loop 1` + `-shortest` 排空行为不可控 | 显式 `-t <音频时长>`，不用 `-shortest` 猜 | `\|video\_dur − audio\_dur\| ≤ 0.05 s`，不过即 FAIL |
| 3 | 字体未生效（`Fontname` 填了文件路径，且该文件不存在） | 字段语义用错 | 字体表 + 真实族名 + `fontsdir` | 族名必须在字体表内，否则 FAIL |
| 4 | mp3 实测 160k（配置写 192k） | 22050 Hz 下 Layer III 上限 160k，ffmpeg 静默钳制 | 参数可行性校验，不可达即报错 | 产物实测码率 == 配置码率 |
| 5 | 脚本估值比实测高 18–27% | 系数 4 字/秒，实际约 5 | 实测校准闭环 + 反推目标字数 | 偏差 ≤ 8%，超阈告警 |

| 7 | 一期三份副本（`ep_001_P1` / `ep_001_...` / `ep_002_...`） | 编号用 `len(existing)+1` + `exist_ok=True` | 项目目录 = 时间戳 + slug，**已存在即报错**；产出 `manifest.json` 标明发布版 | 目录冲突即 FAIL |

| `/api/engines` | TTS 引擎列表与可用性（edge 的客户端库是否安装、qwen3tts 本地服务是否在线） |
| `/api/backends` | LLM 后端列表与当前值 |
| `/api/llm/models` | 后端可用模型列表 |
| `/api/task/{id}` | 任务状态与进度 |
| `/api/projects` | 已产出的集列表（读 `manifest.json`） |
| `/api/report/{project}` | 某集的校验报告 |

### POST

| 路由 | 功能 |
|---|---|
| `/api/ingest` | 文件上传 / 文本摄入（含书稿锚点切章） |
| `/api/estimate` | 字数↔时长换算（含目标反推） |
| `/api/script/generate` | 起一个写脚本的后台任务，返回 `task_id`（进度与中止走 `/api/task/<id>`） |
| `/api/script/gate` | 对当前脚本跑门禁，返回逐条结果 |
| `/api/tts/preview` | 音色试听（短句） |
| `/api/render` | 起合成任务，返回 `task_id` |
| `/api/assets/regenerate` | 重生背景图 / BGM / 封面 |
| `/api/config` | 合并写配置（部分键） |
| `/api/backend` / `/api/backend/test` | 后端设置与连通性测试 |

业务错误一律 `ok:false` + `error`，HTTP 仍 200；`/api/render` 立刻返回 `task_id`，前端轮询进度——**不再同步阻塞**。

## 十、界面设计

深色单页，四 Tab，完全自包含（无 CDN、无 emoji、CSS/JS 内联、仅系统字体与内置字体）。

## 十三、方法论对齐（《我思故我写》）

理论来源：`Cogito_Scribit/book/appendix/提示词示例.md`（附录 E 元提示词 + 三体骨架）、07 四原则、08/08a/08b/08c、09b/09c/09d/09e、10 划界权。**本智能体自身须过附录 E 的"审查时提示词"八节检查。**

### 13.1 契约五层（L1–L5）

`PROTOCOL.md` 按五层书写，`selfcheck` 脚本校验五层完整性。

| 层 | 内容 |
|---|---|
| L1 身份 | Podcast Maker v0.1.0 | 作者 wUwproject | Apache 2.0 |
| L2 触发与能力 | 用户提供素材与要求时调用；能写脚本、合成声音、烧字幕、出成片与封面；**不能**发布到平台、不能做声纹克隆、不能生成人脸、不能替用户决定风格 |
| L3 行为约束 | fail-closed（LLM 不可用即报错，不静默兜底）；脚本必须落进模板；同一人连说不超过范式卡上限；时长偏差超阈即回灌；文案忠于素材，禁编造；门禁不过不给产物 |
| L4 接口 | HTTP API 表 + `script.json` schema + 产物清单 + CLI 参数 |
| L5 数据 | `config.json`、`projects/<集>/`、`calibration.json`、`locks/`、`report.json` |

### 13.2 确定性特权：能写代码的，绝不交 LLM

这是全案第一条硬规矩，直接决定模块分工。

| 环节 | 归属 | 理由 |
|---|---|---|
| 字数统计、时长换算 | **代码** | 可精确计算，不可争议 |
| 同一人连续句数校验 | **代码** | 有阈值判据（上限取自范式卡） |
| 句长 / 单句时长校验 | **代码** | 有阈值判据 |
| 字幕断行 | **代码** | 禁则表可枚举 |
| 情绪标签合法性 | **代码**（受控词表成员判定） | 可枚举 |
| 编码参数可行性 | **代码**（查表） | 有限枚举 |
| 音画时长对齐 | **代码** | 可测量 |
| 封面/背景/BGM 生成 | **代码** | 纯图形与信号合成 |
| 台词文本生成 | **LLM** | 内容轴，不可穷举 |
| 素材语义解析 | **LLM** | 语义理解 |
| 风格化改写 | **LLM** | 概率任务 |

### 13.3 统一推动点位（09b）：唯一声明层

**`config_manager.PARAM_SPEC` 是唯一的推动点位。** 界面控件的值域与默认值、后端校验规则、流水线执行参数、文档描述，全部由这一张表派生。改一个行为 = 改表里一行。

配套三张有限枚举表：

| 表 | 内容 | 枚举性质 |
|---|---|---|
| `PARAM_SPEC` | 全部可配置点位：key / 类型 / 默认 / 范围 / 归属组 / 消费者 | 封闭表 |
| `MODE_SPEC` | 枚举型点位的档位定义（动画、说话人、字幕、封面、BGM、背景） | 封闭表 |
| `GATE_SPEC` | 门禁条目：判据、阈值、级别、失败动作 | 封闭表 |

**明令禁止**（对应 09b"分散点位 = 乘积级枚举成本"）：

1. 页面里写第二份值域（`min`/`max`/`step` 必须由后端下发）
2. 模块内写魔法数字（阈值一律取 `GATE_SPEC`）
3. 提示词里藏阈值（阈值不得出现在 prompt 中，prompt 只说"按系统要求"，判据由代码执行）
4. 同一物理量在多个模块各存一份

### 13.4 前置规范大于后置验证（08a）

**生成脚本之前，以下内容已确定性定稿**（不交给 LLM 决策）：

| 前置项 | 形态 |
|---|---|
| 脚本 JSON 模板 | 字段名、类型、顺序、必填性 |
| 片头/片尾固定台词 | 模板字符串，含占位符；**整期定稿那一刻由程序粘上，不进提示词、不参与生成**（`glue_intro_outro`，见 §17.10、§17.14） |
| 受控情绪词表 | 封闭集合 |
| 风格预设七维取值 | 封闭枚举 |
| 四项内容禁令 | 正则 + 关键词规则表 |
| 门禁阈值 | `GATE_SPEC` |
| 字幕禁则字表 | 封闭集合 |

**LLM 只填两个空**：台词文本、情绪标签（从词表选）。其余全部由代码确定性完成。

### 13.5 空是外部考试（08b）：格式轴硬编码，内容轴不承诺收束

| 轴 | 处理 | 理由 |
|---|---|---|
| 格式轴（字段、编号、排序、字数） | **Python 硬编码收束** | 可穷举，确定性后处理是最高锚点 |
| 内容轴（台词说什么、怎么说） | 交 LLM，**不承诺收束到点** | 不可穷举，承诺即虚假 |

### 13.6 提示词三查（09e）：下发给 LLM 的每条指令都要过

可枚举？可定位？可验证？三查不过即改写为结构指令，或退回代码。

原项目 prompt 里的语句逐条判决：

| 原 prompt 语句 | 可枚举 | 可定位 | 可验证 | 判决 |
|---|---|---|---|---|
| "每句台词控制在 8~40 字之间" | 是（区间） | 是（逐句） | 是（len 可测） | **保留** |
| "A 和 B 交替说话" | 是（二元） | 是（句序） | 是（可判） | **改写**为：说话人由内容定，同一人可连说（上限见范式卡）——「交替」写死会把一个人的一段话劈成两个人 |
| "有来有回，像真人在聊天，不要念稿" | 否 | 否 | 否 | **删（死板废话）** |
| "内容要口语化、有情绪、有互动感" | 否 | 否 | 否 | **改写**为可验证结构：口语标记词密度 ≥ 阈值 / 情绪标签必须取自受控词表 / 问句占比区间 |
| "开头要有吸引力的引入" | 否 | 是（首句） | 否 | **改写**为：片头语是固定结构、程序在整期定稿那一刻粘上，模型**不写**它——它的第一句直接进入内容，不做报幕 |
| "总时长尽量贴近用户要求的 target_minutes" | 是（区间） | 是（全篇） | 是（可测） | **改写**为：给出目标有效字数并附偏差判据 |

**新 prompt 的硬性要求**：每条指令必须能填进"范围 / 位置 / 判据"三格；填不进的不写。所有阈值不出现在 prompt 里，由代码执行。

**每块自报身份**（见 PROTOCOL 3.3.1）：一条提示词里塞着素材、参考、当前任务、输出
契约好几样东西，块名说「这是什么」、括注说「怎么用」。三查管的是**指令本身**合不合规，
分块管的是**资料的归属**说不说得清——两者互补：指令条条合格、资料混作一团，模型照样
分不出哪块是依据、哪块是这一步要它交的东西。

### 13.7 六检（09d）：生成后六维检查

| 检 | 播客适配 | 实现 | 范式（09c） |
|---|---|---|---|
| 格式检 | 字段齐、类型对、编号连续 | **代码** | 确定性 |
| 连续性检 | 相邻句话题衔接（B 的回应接住 A 的落点） | **代码**（关键词重叠）+ 复用轮 LLM | 确定性优先 |
| 承诺链检 | 正文开头提出的设问，后文有回应（报出承诺句 + 建议闭合位置，定点插一句回应） | **LLM**（判据是正文，片头尾不在这份稿子里） | 确定性优先 |
| 逻辑检 | 无自相矛盾（否定冲突、数值冲突） | **代码**（规则表） | 确定性 |
| 语义检 | 台词忠于素材、未编造 | **LLM**（推理范式，非匹配） | 不做余弦相似度判断 |
| 推理检 | 论证链成立、因果不跳 | **LLM**（推理范式） | 不做匹配 |

前四检为硬门禁（不过即定点修补），后两检为报告项（不过即标记，交人判断——划界权在人手里）。

### 13.8 划界权留在人手里（10/10a/10b）

| 决策 | 归属 | 说明 |
|---|---|---|
| 风格预设选择 | **人** | 界面下拉，LLM 不选 |
| 动画 / 说话人 / 字幕档位 | **人** | 界面选择，LLM 不选 |
| 门禁阈值是否放宽 | **人** | 配置项，LLM 不得修改 |
| 后两检（语义/推理）是否放行 | **人** | LLM 只给报告，不给判决 |
| 台词内容 | LLM | 既定边界内的填空 |

**不做超范围承诺**（10b）：不承诺"节目有温度/有共情"，输出限定在识别与表达层。

### 13.9 fail-closed 与锁文件（08a）

| 情形 | 行为 |
|---|---|
| LLM 后端不可达 | 报错退出。**不**静默降级、**不**用空脚本续跑、**不**假功能 |
| 素材抽取为空 | 报错。**不**返回空串继续 |
| 门禁连续 3 次不过（脚本阶段） | 稿子与结论一起落盘（`脚本/<期号>.json` + `过程/<期号>/gate.generate.json`），**不拦人**；合成前弹一次提醒，改稿或照出由人定 |
| 产物门禁不过（合成阶段） | 写 `过程/<期号>/blocked.lock.json`（字段：`blocked_at` / `reason` / `context` / `attempts`）**留痕**；产物落了盘就出片、就记账，过没过写进报告 |
| 中断恢复 | `--continue <集>` 读取锁文件，从阻断点续跑，修复后清锁 |
| 重试上限 | 3 次（`GATE_SPEC.retry_max`） |
| 空转上限 | 3 次（`GATE_SPEC.idle_max`） |

### 13.10 四原则（07）自查

| 原则 | 本案自查 |
|---|---|
| 如无必要，勿增实体 | 不做"将来可能用到"的模块。emotion 若定稿为无人消费，即从协议删除 |
| 如无规矩，勿增操作 | 不存在无规则的自由 LLM 调用入口，一切调用点必有门禁与模板 |
| 如无能力，勿增限制 | 不要求 LLM 输出精确字数或精确秒数——它做不到，故不给它设这类约束 |
| 如无资源，勿增承诺 | 有锁文件机制才承诺可恢复；有校准样本才承诺校准有效 |

## 十四、自动生成方案（固定模式枚举）

原项目"封面自动生成"是好的做法，保留并推广：**每一个可视化/可听化要素都必须有自动生成路径，且档位固定可枚举**（09b：有限枚举，封闭表）。

### 14.1 七要素总表

| 要素 | 原项目 | 新方案 | 档位数 |
|---|---|---|---|
| 背景图 | 自动（SVG→Edge→Pillow 水印） | 保留并参数化，配色/文案/水印全走配置 | 3 档 |
| 封面 | 半自动（复制背景图） | **升级为独立生成**，三尺寸（16:9 / 3:4 / 1:1），标题/期号/副标模板化 | 3 档 |

| key | 名称 | 说明 |
|---|---|---|

### 14.3 生成链路位置

```
素材 → 脚本（LLM）
     → 背景图（代码生成）─┐
     → BGM（代码生成）────┤
     → 封面（代码生成）───┼→ 声音合成 → 音频后处理（叠 BGM）
     → 字幕（代码断行）───┤                    ↓
     → 动画档位（配置）───┴──────────→ 画面合成（背景+动画+指示+字幕）
                                              ↓
                                          产物 + 校验报告
```

**七要素除"脚本"外全部由代码生成，不调用 LLM**（确定性特权）。档位由人选定，不由 LLM 选（划界权）。

## 十七、段划分：按输入额度装箱（2026-09-18 定稿，v0.16.0 已实施）

> 本节群按时间顺序记当时的结论。**凡与 §17.15（v0.22.0）冲突的，以 §17.15 为准**——
> 17.3 的「按原文位置切块」、17.4 的「单节切块数超顶 / 一段最多合 3 节」两条边界，
> 以及 17.7 的「切段是纯算术、模型不碰边界」那一整套分工，都已被它推翻。

### 17.1 问题：段是按"写多少字"分的，不是按"装多少料"分的

一期脚本要分几次写完，取决于**一次调用装不装得下**。一次调用里要装三样：

```
提示词 + 已写正文（前面各段的成稿）+ 本段要读的原文
```

三者相加超过单次额度时，现行为是**把原文整份丢掉、换成凝缩**
（`script_engine.fit_material:1018-1023`）——产出一期"照骨架写"的薄稿，
且日志里只有一句"已改用凝缩"。

根因不在降级本身，在**段划分的依据错位**：

| 错位处 | 现状 |
|---|---|
| 段怎么分 | `_segments_plan` 让模型按"逻辑完整 + 体量均衡"分组，`_allocate_segment_quotas:2031-2040` 按**凝缩字数占比**分配额 → 段的大小由**成稿字数**决定 |
| 装不装得下怎么判 | `fit_material:1000-1006`：`material_capacity(cfg) - other_chars`，两边一个**朗读字数**、一个**字符数**，再拿**字符数**去比 |
| 规划轮知道什么 | user prompt 只给"凝缩 N 字"（`_seg_weight`）与"素材共约 N 字"（整期、字符口径）→ **逐节的原文体量根本不在输入里** |

三处叠加的结果：一期 6.4 万字符的技术文档，在"朗读字数"那把尺下压比合格，
到写作侧被判"超出容量"，原文一个字没进 prompt。

### 17.2 定案：三层各管各的，各用各的尺

| 层 | 回答什么 | 尺 | 不合格怎么办 |
|---|---|---|---|
| **画地图** | 这一期该讲多少料 | 压比 / 朗读字数（汉字 1、标点 0.5、西文按词 1.5、符号 0） | 重排；重排两轮仍超则报错，要求拆期 |
| **单次调用** | 这一次能装多少 | **token**：额度 = 最大输出 × `llm.input_ratio` | 调倍率（后端窗口不归程序管，由使用者自己开） |
| **划分段** | 这些料要分几次喂完 | 装箱 | **多切一块，绝不丢原文** |

三层互不干涉：倍率调大调小，地图一个字节不动；改时长改档位，倍率也不用动。

**单位只有一个：token。** 原文（字符）折 token 后与额度同单位比较；折算
用后端回传的真实 `prompt_tokens` 反标（`llm_client.tokens_per_char`），
冷启动无样本时按 1 字符 = 1 token 顶格算，再叠 `INPUT_RESERVE_FRAC` 余量。
**折算只准偏保守**——估高了浪费额度，估低了直接顶爆后端。

### 17.3 装箱算法

```
桶容量(段 i) = 输入额度 − 提示词 − 固定占位 − 已写正文(前 i−1 段配额累计)

for 节 in 顺序（顺序不可打乱，讲述顺序由地图定死）:
    若 节重量 ≤ 当前桶剩余        → 装入当前桶
    否则若 当前桶非空             → 封桶，开新桶再试
    否则（节重量 > 桶容量）       → 该节切块：ceil(重量 / 桶容量) 块，按原文位置均分
```

**桶容量逐段递减**——因为已写正文在增长。

**不扣本段自己的输出**：`input_ratio` 量的是**输入额度**，本段成稿占的是**输出额度**
（`max_tokens`），两者分开。`fit_material` 现在的 `other_chars` 也只扣
`system + prev_text + extra + 固定占位`，不含本段输出——原式里那一项是多扣的。

规划阶段"已写正文"= **前面各桶的节配额之和**（配额在装箱前已算完，是**确定值**，
不是估算），写入阶段用**实际成稿长度**再算一次兜底。

举例（额度 10000，五节原文 3000 / 8000 / 13000 / 5000 / 3000）：

| 段 | 装什么 | 装入量 |
|---|---|---|
| 1 | 节① | 3000 |
| 2 | 节② | 8000 |
| 3 | 节③前半 | 6500 |
| 3a | 节③后半 | 6500 |
| 4 | 节④+节⑤ | 8000 |

**配额先按节摊**：`q_i = target × w_i / Σw`（`_material_chars` = 这一节的**原文有效字**；
v0.24.0 前取原始字符数、v0.23.0 前取摘要字数，两次都摊歪，见 §17.17 / §17.19），段配额 = **桶内各节配额之和**
——与现行 `_allocate_segment_quotas:2033` 数学等价（段权重本就是段内各节权重之和，摊派线性）。
被切开的节，两块之间**按原文长度比摊**。

（上表是"不扣已写正文"的简化示意；实际桶容量逐段递减，第 4 段能否合并④+⑤取决于前面各段配额累计。）
段内配额、8~40 字一句、少则插句多则压紧等机制**全部不变**——装箱只管段边界。

**要点不切。** 段的 prompt 里凝缩要点照原样全给（切要点需要"要点 ↔ 原文位置"
映射，不存在也不可靠），把「**必须全部讲到**」改成
「**已写正文讲过的不要重复；只用本块原文，补还没讲到的**」——
已写正文本来就在上下文里（`script_engine.py:2615-2616`），
于是被切开的块自然分工：前块讲前半、后块只补剩余的点。

### 17.4 边界

| 情形 | 处理 |
|---|---|
| 单节切块数超顶 | 报错要求回地图拆期，不许无限切（顶对齐内容检的 `CHECK6_MAX_BATCHES = 8`） |
| 一段合并的节数 | 设上限（建议 ≤ 3 节）——合并段的配额是各节之和，过长会重新踩"一次写太长会漂移" |
| 段内仍超（单块就超大） | **分批喂完**（对齐内容检的 `split_material`），禁止"换凝缩 / 截断"作为唯一出路 |
| 额度不够（桶容量 ≤ 0，或某节切块数超顶仍装不下） | **报错要求调大 `input_ratio`**（或减小成稿目标 / 拆期），不许无限切。"已写正文"是硬开销，额度是它的上限 |
| 同名标题消歧 | `evidence_pack:398-401` 组节时补回 `line`——取原文时 `compose` 支持它，丢了会取错节 |

### 17.6 职责边界与连带改动（2026-09-18 补：流程顺序确认）

**装箱在前、规划轮在后 —— 顺序正确**，但规划轮的职责要相应让位。

现在的规划轮（`_segments_plan:2523`）**本身就是分段轮**：一次 LLM 调用同时产出
「本期标题 + 每段覆盖哪几节 + 每段一句话题目」。装箱前置后：

| 归程序（算术） | 归规划轮（内容） |
|---|---|
| 段边界：哪几节进哪段、超重节切块 | 本期标题 |
| 每段配额数字 | 每段一句话题目（讲什么、从哪起、到哪止） |

**三处连带改动（不跟上，顺序对了也跑不通）：**

| # | 冲突点 | 现状 | 必须改成 |
|---|---|---|---|
| A | `_segment_plan_schema:1917-1921` | `sections` 是**模型必填** → 模型在分段 | 删 `sections`，模型只填 `title` + 每段 `topic`；数组长度用 `minItems = maxItems = 段数` 钉死（段数由 py 给） |
| B | `_validate_plan:2022-2024` | 同一节出现在两段 → **直接打回**（理由"会被写两遍"） | 装箱后**整条失效**：段由 py 定、模型不再碰 `sections`。校验改为「topic 条数 == 段数、顺序对齐」；切块合法性由 py 自己保证 |
| C | `_segment_plan_user:1987` | 指令是"把凝缩要点**分组**，输出 segments" | 改为「段清单已定，逐段写题目」；段清单（含 `{sec, part}` 与原文范围）由 **py 组装**后喂进去 |

**topic 只写"讲什么"**：切块后写作模型手里只有本块原文，topic 若写"讲第 3 节的全部内容"，
它会去写没拿到的部分。但"从哪起、到哪止"**由 py 的范围描述给死**（第 3 节第 2 块、
覆盖原文哪一段），topic 不再重复这件事——两处都写必然互相打架。规划轮的任务因此只剩
"给这段内容起个说法"，它既不需要知道、也不能改段边界。

**配额不需要估，先算即可（2026-09-18 修正）**：`_allocate_segment_quotas:2033` 的段权重是
**段内各节权重之和**，而摊派是线性的 → 段配额 ≡ 段内各节配额之和。所以「先按节摊、
再装箱、段配额 = 桶内节配额之和」与现行算法**数学等价**（加法可交换）。

原先写的「鸡生蛋」（桶容量要配额、配额要分组、分组来自装箱）**不成立**——配额与分组无关。
装箱前先把每节配额算完，装箱时 `written`（已写正文）= 前面各桶的节配额之和（折 token），
全程是确定值：**无估计、无迭代**。

### 17.7 切段是纯算术：py 五步流水线（2026-09-18 定案）

装箱、切块、块序号、每段配额 —— **全部由 py 算完，LLM 不参与任何切分**。

```
① 每节权重   w_i = _material_chars(节 i)                       # 凝缩对应的原文量 loc.chars
                                                              # （v0.23.0 前是 gist+points 字数，见 §17.17）
② 每节配额   q_i = target_chars × w_i / Σw                     # 余数补给最大的节
③ 每节原文   t_i = material_tokens(len(compose([ref_i])))      # 字符 → token（含余量）
④ 装箱       written = 0
             for i in 1..n:
                 avail = 输入额度 − 提示词 − 固定占位 − written
                 if    cur_tokens + t_i ≤ avail  → 装入当前桶
                 elif  当前桶非空                 → 封桶；
                                                   written += material_tokens(桶内 q 之和)；
                                                   开新桶重试
                 else                            → t_i > avail：该节**自身超额度，报错**
                                                   （v0.22.0 前是切成 k 块，已撤销，见 §17.15）
⑤ （已撤销）块配额 q_块 = q_i × 该块原文字符数 / 整节原文字符数
             ——切分单位统一到**整节凝缩**，块不存在了，见 §17.15
```

**块序号由 py 打**：`{"sec": 3, "part": 1}` / `{"sec": 3, "part": 2}`。段的"范围描述"
（第 3 节第 1 块、覆盖原文哪一段）同样由 py 写进提示词 —— **模型要读的东西全是 py 组装的**，
模型只回"标题 + 每段一句话题目"。

**折算工具现成**（`llm_client:296-345`）：

| 需要 | 函数 |
|---|---|
| 字符 → token（含 `max(1024, 8%)` 余量） | `llm.material_tokens(字符数)` |
| 每字符折多少 token（有样本取中位数，无样本 **1.0** 最保守） | `llm.tokens_per_char()` |

（`material_tokens` 名字偏"素材"，实现就是通用的 `chars × 比 + 余量`；"已写正文"同样适用。）

**余数/下限的落点变了**：现行把「余数补给最大段」「下限 60 字」加在**段**上
（`_allocate_segment_quotas:2037-2039`）；改成先摊到节之后，这两条要落在**段**这一层
（段配额 = 桶内节配额之和，再统一补余数、抬下限）。

### 17.9 收口：后端窗口退出程序职责（2026-09-18，v0.17.0）

### 17.10 收口：片头尾由「替换」改「粘合」，并移出生成链（2026-09-18，v0.18.0）

主人口径一句话定死：

> 全部都是引用，直接 py 可以固定生成，那么它们就可以放到所有门禁和验证之后，不管是否通过，
> 只要脚本落盘就直接粘合。这样既不会扰乱脚本生成过程中的门禁和检查，也正确地增加了开头和结尾。

**修的是什么**：某项目 5 期脚本，第 1 句是写死的问候语，第 2 句却全是「没错…」这类**回应式**
开头；倒数第二句是提问，紧跟着就是片尾问候语，答案句不存在。听感上就是对着空气点头、问题
永远悬空。根因不在模型：`pin_intro_outro()` 名为「写死首末句」，实为**替换**首末句——拿片头句
盖掉正文第 1 句、片尾句盖掉正文最后 1 句。句数不变，`gate.intro_outro` 只验首末句像不像片头尾，
所以恒过；而分段路的提示词又明确要求模型「不要问候（片头）或收尾（片尾）——它们由程序按模板
补齐」。两头一合，**每期正文头尾各丢一句**。

| 项 | 从前 | 现在 |
|---|---|---|
| 落地方式 | **替换**正文首/末句（`pin_intro_outro`） | **粘**：头加片头、尾加片尾，正文一句不动、一句不删（`glue_intro_outro`） |
| 时点 | 生成循环内（写完即改） | **整期定稿那一刻**（`_glued_draft`；v0.18.0 时说的是「落盘与返回那一刻」，v0.21.0 收窄为定稿一次，见 §17.14）；循环、门禁、修补、核账看到的自始至终只有正文 |
| 模板形态 | 两个字符串（`intro_first` / `outro_last`） | 句子**列表**（`{intro: […], outro: […]}`，各带 `speaker`/`emotion`/`text`）——片头本来就不止一句 |
| 门禁 | `intro_outro`（fail，判首末句像不像模板） | **删除**，连同判据函数 `intro_outro_ok` 与常量 `INTRO_MARKS`/`OUTRO_MARKS` |
| 提示词 | 请模型照抄首末句；内容检再为其开一条豁免 | 【片头片尾】明说「不归你写，一句都不要写」；豁免一并删掉（呈给内容检的就是正文） |
| 片头里的受众 | 无此字段 | 项目级 `audience`：画地图时问一次 → 落项目 → 界面可改 |
| 缺料 | —— | 受众/称呼缺 → 那一小段消失；期标题缺 → 「本期讲述…」整句不粘 |

**为什么粘合必须后置**：一是片头尾是逐字拼出来的固定结构，让格式门禁（同一人连续句数、句长）
去掰它，只会把固定标识掰歪；二是定点修补按**句号**改句子，粘在循环内会让正文句号整体后移两位，
「第 N 句」指的是谁全漂。

**为什么受众是节目级**：它印在每一期片头里，同一档节目各期必须逐字一致；每期各生成一次必然
漂移，那就不是节目的标识了。取值只有一条路：排地图时模型给第一版 → 落进项目 → 界面可改。
四条纪律：模型只认第一版（重排不覆盖）、**人填过一律不覆盖**（同 `planned_episodes`）、
无地图的项目（单集、逐期即兴）留空、通路是 `project.audience` 通道键（不由人配在设置页）。

**连带的量**：门禁 21 → **20**（生成阶段 13 → 12，fail 17 → 16），因为撤掉的那条原本是 fail 级。

**已生成的稿子**：该 5 期脚本都带这个伤，需重出；本版只保证此后不再出现。

### 17.12 收口：片头尾只在「整期终稿」粘一次，段间不粘（2026-09-18，v0.20.0）

**怎么发现的**：主人看第 1 期（1/6）的运行日志，段 1 写完那一行紧接着就是
「片头尾已粘上：正文 129 句，首 2 句、尾 1 句固定结构」，于是问：**「为什么段就贴了？
应该是整期完成的时候贴片头片尾，你这分两段要贴几次？」** —— 问得对，这是 v0.18.0 落地
时我自己带进去的漏。

**根因**：粘合挂在「每次写盘」这个动作上，而不是挂在「整期终稿」这个点上。
`_generate_segmented` 段间落盘时调了 `_glued_draft`，于是**每一段写完都粘一遍**。
同一个函数的调用方 `generate` 里写着「片头尾不在这里粘：门禁与定点修补看到的只能是
正文，粘合在落盘与返回那一刻做一次」——两处说的是两套规矩，段间那条是后加的、违背了
另一条。

**为什么这不是小事**（比「多粘几遍」严重）：

| 后果 | 说明 |
|---|---|
| 中间产物形态像成品 | 段 1 落盘的稿子已经是「片头 + 段1正文 + 片尾」。片尾挂在半篇的末尾，内容只写了一半，可形态与一整期一模一样 |
| 中止时交出的就是它 | 每次写盘都覆盖同一个正式脚本位（`layout.script_file`），所以中途被中止／进程被杀，手上那份是「半期 + 片头 + 片尾」，看不出残缺 |
| 日志误导判断 | 「片头尾已粘上」这句日志出现在段 1 之后，读日志的人会以为整期完事了 |

**结论**：粘合是「成品封装」，成品只有一个；中间产物一律是裸正文。

| | 改前 | 改后 |
|---|---|---|
| 段间落盘（`_generate_segmented`） | `_glued_draft(...)`，每段粘一遍 | 裸正文 + `report.partial = True` |
| 整期落盘（`generate` 循环内） | `_glued_draft(...)` | 不变（每轮仍粘一次，落盘就该是成品形态） |
| 返回（门禁通过 / 兜底两条出口） | `_glued_draft(...)`，与该轮落盘各粘一遍 | 复用该轮已粘的那一份（见 §17.13） |
| 粘几次 | 段数 + 1 | **每轮 1 次**，等于该轮的落盘次数 |

**约束写在哪**：`_glued_draft` 的 docstring 里点明「只许喂整期终稿，不许喂任何中间
产物」，并列出全部三个调用点——这个函数看着通用，实际只有整期终稿能用，说明写在函数
自己头上，下一个读的人不用去猜调用现场。

**测试**：`test_segment_drafts_are_not_glued`（段间落盘的稿子首句不含「欢迎收听」、
末句不含「欢迎关注」，且带 `partial` 标记）、
`test_whole_episode_glues_the_fixed_lines_exactly_once`（首 2 句片头、尾 1 句片尾，
且全篇「欢迎收听」「欢迎关注」各只出现一次——按句数对得上不足以证明，正文凑巧提到
同样的字也照样数得对）。**881 项全绿。**

### 17.13 收口：同一轮内「落盘」与「返回」共用一次粘合（2026-09-19，v0.20.0）

> **本节结论已被 §17.14 推翻**（2026-09-19，v0.21.0）：这一节把问题定义成「同一轮里粘了两遍」，
> 于是只治了「一轮一次」。正确的口径是「**整期一次**」——中间轮次的落盘压根不该粘。本节保留
> 下来是因为它记录了一次「治了症状、没治病」的判断，以及主人一句话点破的那句质问。

**怎么发现的**：主人贴第 2 期的运行日志问「虽然最终显示出来的，的确是正确的片头和片尾，
但是为啥日志这里显示这么多遍？」——一轮里三行，两轮跑下来三行：

```
[00:56:37] 片头尾已粘上：正文 213 句，首 2 句、尾 1 句固定结构
[00:56:37] 门禁未过：1 处（禁用词）
[01:14:22] 片头尾已粘上：正文 213 句，首 2 句、尾 1 句固定结构   ← 第 2 轮落盘
[01:14:22] 门禁通过（第 2 轮）
[01:14:22] 片头尾已粘上：正文 213 句，首 2 句、尾 1 句固定结构   ← 同一轮又粘一遍
```

**根因**：同一轮里「落盘」与「返回」两处各调了一次 `_glued_draft`。第 2 轮既走过
`draft_sink`，又在门禁通过时走 `return`，于是对**同一份正文**粘了两遍。结果没错
（粘合是纯函数，同输入同输出），但日志多出一行「背后什么都没发生」的记录——
读日志的人分不清是粘重了还是落了几次盘。兜底返回那条路同理：最后一轮已经落过盘，
收尾时又粘一遍。

**改法**：每轮只粘一次，用一个局部 `glued` 装住，落盘与返回共用同一个对象。

| 位置 | 改前 | 改后 |
|---|---|---|
| 每轮落盘 | `draft_sink(_glued_draft(last, …))` | `glued = _glued_draft(last, …)` → `draft_sink(glued)` |
| 门禁通过返回 | `return _glued_draft(last, …)`（再粘一遍） | `return glued`（复用；`draft_sink` 为空时才现粘） |
| 兜底返回（轮次用尽 / 中止 / 指不出句号） | `return _glued_draft(last, …)`（再粘一遍） | 复用最后一轮的 `glued` |

**为什么不是「整期只粘一次」**：每轮落盘的稿子都该是能用的成品形态——生成一轮十几分钟，
中途被中止、进程被杀时，手上那份要能直接拿去出片。所以**落盘几次就粘几次**；不许重复的
是「同一轮里对同一份稿子粘两遍」。口径一句话：**一轮一次，日志一行对一次落盘。**

**测试**：`test_glue_runs_once_per_round`（三轮场景下，日志里「片头尾已粘上」的行数
= `draft_sink` 被调用的次数，不是每轮再多一行）、`test_the_returned_script_is_the_sunk_one`
（返回的就是刚落盘的那一份，同一个对象）。**885 项全绿。**

### 17.14 收口：粘合只挂「整期定稿」一个点，中间产物一律裸正文（2026-09-19，v0.21.0）

**怎么发现的**：主人读完 §17.13 的处理方式，直接问：

> 没看懂你的逻辑，不应该是本期所有轮都完成后再粘贴吗？因为片头片尾又不需要进入轮、不需要门禁、
> 不需要验证，他应该就是这一期不管多少轮修改不管修改成功与否最终落盘的那一份增加的片头片尾，不是吗？

**问得对，§17.13 治错了病。** 那一节把问题定义成「同一轮里粘了两遍」，于是改法是「一轮只粘一次、
落盘与返回共用一个对象」——症状从三行日志压到两行，可**多出来的那一行仍然什么都不对应**。
真正的口径是：**粘合是「这一期交出一份成品」这一个动作**，不是「每写一次盘」的附带品。中间轮次
落的盘只是过程稿，给它粘片头尾等于给半成品盖上成品的样子；轮次越多，日志上「片头尾已粘上」
越多，读日志的人越分不清是粘重了还是落了几次盘。

**改法**：把粘合收进一个出口 `_finish()`——粘一次、落盘、返回，全篇只有这一处调 `_glued_draft`。

| | 改前（v0.20.0） | 改后（v0.21.0） |
|---|---|---|
| 循环内每轮 | `glued = _glued_draft(last, …)` → `draft_sink(glued)`（每轮粘一次） | `draft_sink(last)`（裸正文；最后一轮不落，由定稿顶替） |
| 门禁通过 | 复用该轮的 `glued` | `return _finish(last)` |
| 兜底返回（轮次用尽 / 中止 / 指不出句号） | 复用最后一轮的 `glued` | `return _finish(last)` |
| 粘合次数（N 轮） | N | **1** |
| 日志「片头尾已粘上」 | N 行 | **1 行** |

**为什么定稿必须落盘**：出片读的是盘上那份（`draft_sink` 写的位置），界面拿的是返回值。只粘不落，
盘上留着的就是上一轮的裸正文——看的和念的对不上。

**为什么最后一轮的过程稿不落**：紧接着的兜底出口会把定稿写进同一个文件，同一份文件写两遍是白写。
落盘次数因而仍然等于轮数（不是轮数加一）。

**测试**：`test_glue_runs_once_per_episode`（跑三轮、`draft_sink` 被调三次，日志里「片头尾已粘上」
只有一行）、`test_intermediate_drafts_carry_no_fixed_lines`（中间那几份首句不含「欢迎收听」、末句
不含「欢迎关注」；定稿那份两句都在，且返回的就是落盘的那一份）。**887 项全绿。**

### 17.15 收口：切分单位统一到整节凝缩，逻辑拆分独立成一步（2026-09-19，v0.22.0）

**起因**：主人逐条问出三件事——

> 1. 我虽然不懂什么挡路了，但是我明白流程，现在是 py 桶根据输入额度 − 固定开销 − 已写正文直接切段落，
>    而我要的是，先逻辑切段落，得到的是这一段有哪几个凝缩，下一段几个凝缩，再下一段几个凝缩……然后
>    py 桶循环每一段，按照输入额度 − 固定开销 − 已写正文看看是否装得下……
> 2. 逻辑分段之后，如果某段超出 py 桶，直接切分一个或多个完整的凝缩。也就是说，自此，不管是逻辑分段
>    还是后面的 py 桶分段，都按照完整的凝缩进行切分。
> 3. 补足要增加正反例的提示词解释——你只说名词，没有正反例，不解释，犯了名词不解释就等于没有名词的错误。

**定案一：段边界分两步走，各有各的判据。**

| 步 | 谁做 | 管什么 | 判据 | 落在哪 |
|---|---|---|---|---|
| 逻辑拆分 | 模型 | 哪几节讲的是同一件事 | 语义 | `split_by_logic` |
| 逐段过桶 | py | 装得下就整组一段、装不下在组内按整节切 | 容量 | `pack_segments(groups=…)` |

**它是独立的一步，不是并进规划轮。** 逻辑拆分只产「哪几个节成一段」，不产标题、不产题目、
不产任何数字；规划轮拿到的是同样形状的 `groups`，无感。

从前禁止模型分组的理由写在 `_segment_plan_schema` 的注释里：

> 段边界由装箱算好了：让模型再分组，它分出来的就是第二套段划分，与装箱结果打架——两边都去定边界，
> 边界就不存在。

**那条理由只在「分组与装箱并存」时成立**（§17.3~§17.8 那一版就是并存：分组与算术都想去定边界）。
现在装箱不再定边界、降级成容量校验，边界只有一个来源，前提消失。防重排照搬 `planner._clean_groups`
（`planner.py:167`）那三道归一——排图怎么防重排，分段就怎么防：越界/重复序号丢掉并记下 → 组内按
序号升序、组间按各组首序号排序 → 漏掉的节补成独立一段；末尾 `flat == sorted(flat)` 兜底。

**定案二：切分单位只有一个——整节凝缩。** 两条旧上限随之撤销：

| 撤销的 | 原用途 | 为什么撤 |
|---|---|---|
| `SEGMENT_MAX_PARTS = 8` | 单节自身超额度时按**字符位置**切成几块 | 半个节取不出原文（`source_store.compose` 一次只认一个落点），也算不出账 |
| `SEGMENT_MERGE_MAX = 3` | 一段最多合并几节 | 段长由**输入额度**管，不由节数管；逻辑分段已按语义定好「哪几节是一件事」，再拿常数卡它＝把语义边界交回算术 |

单个节自己就超额度时**报错**（要求调大 `llm.input_ratio`，或回地图拆期）。不许无限往下拆——
主人原话：「不可能要求我无限拆下去，不能不够了永远去拆，拆到最后几千字调用十几次完全没意义」。

**定案三：数字同源，全是加法。**

| 量 | 怎么来 | 算子 |
|---|---|---|
| 段 token | 段内各节 token 之和 | 加 |
| 段配额 | 段内各节配额之和 | 加 |
| 段原文 | 段内各节原文按序拼（refs 全是整节） | 拼 |

§17.3 那个「块配额 = q_i × 该块原文字符数 / 整节原文字符数」的除法**连同它的误差一起消失**。
那不是阈值没调好，是两把尺：同一节里 §17.3 明写「**要点不切**」，块拿到的配额是半节的、
拿到的凝缩要点却是整节的——配额一把尺、内容另一把尺，两边不同源时数字必然对不上。

**定案四：补字提示词配正反例。** 「不许重复」只给名词等于没给判据——判「意思重不重复」的人
和被管的人是同一个，它永远判自己合格。改为**算重复**与**不算重复**各三条实例：

| 算重复 | 为什么 |
|---|---|
| 换个词问同一件事 | 「性能开销会不会显著增加」vs「性能开销会不会突破可接受范围」——字面零重合，事没变 |
| 换个词答同一件事 | 「调用频次下降」vs「调用次数减少」——同一句话 |
| 前一句还没答，后一句就替它下结论 | 最隐蔽的一种：问的事没人回答，后面已经定了性 |

| 不算重复 | 为什么 |
|---|---|
| 背景一样，问的是另一件事 | 背景相同不算重复（性能开销 vs 日志体积） |
| 同一件事补上了新的细节 | 加了位置和数字，听众听到新东西 |
| 同一个点把另一条路补上 | 补的是另一条分支的情况 |

例子之后收成一句可用判据：并排放进听众耳朵里听一遍，听到「同一件事又说了一遍」就是重复，
听到「新东西」就不是——**换个说法不改变这个判断**。同时把「一个信息点可以拆成问答两句」
收紧为「一句就够，最多一组一问一答」：允许"两句"等于允许扩张成两问一答拿它凑字数。

**改法**（`script_engine.py`）：

### 17.16 补记：日志把两个量分开命名（2026-09-19，v0.22.1）

v0.22.0 跑出真实日志后，主人指着这几行问「分段生成后开始逻辑拆分？逻辑拆分完了又进行分段？
py分段不是要在逻辑分段之后吗？」——**顺序一直是对的，是日志把同一个字用在了两个东西上。**

原日志：

```
分段生成：逻辑拆分开始（3 节，全篇目标约 6024 字，单次输入额度 47872 token）
逻辑拆分完成：2 段（第1段：第1节、第2段：第2–3节）
分段生成：装箱开始（逐个逻辑段过输入额度）
装箱完成：2 段，配额合计 6024 字（…）
```

两处毛病：①`分段生成：` 这个前缀挂了两次（逻辑拆分前、装箱前），看着像分段做了两遍；②两个
`2 段` 指的是不同东西——前者是模型按**内容**分的组，后者是真正分别喂给模型的段，这次刚好都
是 2，更像「同一步跑了两遍」。另外装箱才用得上的两个数（目标字数、输入额度）被挂在逻辑拆分
那一行，逻辑拆分并不用它们。

**定案：给两个量各自的名字，给两步编号。**

| 量 | 名字 | 谁定的 |
|---|---|---|
| 模型按内容把节归成的组 | **逻辑段** | 逻辑拆分（`split_by_logic`） |
| 真正分别喂给模型的段 | **写作段** | 装箱（`pack_segments`） |

关系：**写作段数 ≥ 逻辑段数**（装得下 → 一个逻辑段落成一个写作段；装不下 → 在组内按整节切成
几个）。日志改成 `分段 · 第1步 逻辑拆分：依据本期主旨与 N 节凝缩…` / `逻辑拆分完成：N 节 →
M 个逻辑段（逻辑段1 = 第1节…）` / `分段 · 第2步 装箱：逐个逻辑段量体量（输入额度 … − 固定开销
− 已写正文，全篇目标约 N 字）…` / `装箱完成：M 个逻辑段 → K 个写作段，配额合计 …`；量不出额度
的后端（假模型）改说「这个后端量不出输入额度，逻辑分组原样落段」，不再打「输入额度 0 token」
（读起来像额度被吃光）。

**功能一行未改**——只动日志文案；文档补上两个词的定义与关系（README 四、产物；PROTOCOL
3.3.4）。**教训**：日志是给人看的账，账里的名词要与文档同一套口径，同一个字不许指两个量。

**测试**：899 项全绿（无断言变更）。

### 17.17 收口：配额权重换成「凝缩对应的原文量」（2026-09-19，v0.23.0）

**问题**：第 2 期段 2 把自己刚写过的话换着说法讲了 3 遍，去重删掉 64 句。根因不在
提示词，在配额怎么摊。

| 段 | 旧配额 | 段手里的料 | 旧压比 |
|---|---|---|---|
| 段 1（第 03 节） | 1823 字 | 第 03 节 | 3.47（宽松） |
| 段 2（第 04+05 节） | **4201 字** | 第 04+05 节 | **1.50（贴死下限）** |

料多的段少派、料少的段多派，用力方向正好反了。段 2 被派到 1.50 倍——正好贴死地图
那档的最低需求（`MIN_RATIO` 1.2 × 偏移 1.25 = 1.50）。**模型写不满就凑，凑法是把刚
写过的话换个说法再讲一遍。**

**错在哪一行**：`_seg_weight` 取的是 `gist + points` 的字数——那是**摘要自己**写得多
长。而配额问的是「这一段该写多长」，该写多长由**料的多少**定。料有多少，凝缩那一步
早就记下了：`probe._mark_loc` 回填的 `loc.chars`（这一节压的是原文哪一块、那块多大）。
另一个数一直在盘上，只是没人用——`pipeline.evidence_pack` 往下传时只挑了
`source / anchor / gist / line / points` 五项，把 `loc` 整个丢了。

**定案：两把尺分开，各自认领一个用途。**

| 量 | 函数 | 用途 |
|---|---|---|
| 摘要自己的字数（gist + points） | `_gist_chars` | 提示词里展示凝缩的**详略** |
| 凝缩对应的原文量（`loc.chars`） | `_material_chars` | **配额权重** |

`_seg_weight` 一个函数原本被三处共用（逻辑拆分提示词、规划轮提示词、配额摊派），前两处
要的是「凝缩多详略」，只有第三处要的是权重——**一个词一个义**，拆开。§17.7 的
「① 每节权重 `w_i = _seg_weight(节 i)` # gist + points 字符数」一句由本节作废。

改动：
- `pipeline.evidence_pack`：sections 放行 `loc`；
- `script_engine._seg_weight` → 拆成 `_gist_chars` + `_material_chars`；
- `_section_quotas`：权重改 `_material_chars`；`loc.chars` 缺失**报错**，不退回摘要尺
  （退回去等于把摊歪的配额重新摊一遍，而且从日志上看不出来用的是哪把尺）。

**第 2 期实测（全篇目标 6024 字）**：

| | 段 1（第 03 节） | 段 2（第 04+05 节） |
|---|---|---|
| 旧（摘要字数权重） | 1823 | 4201 |

776 字、段 1 多派 776 字。

**未跑一期验证**：以上是算出来的。段 1 配额从 1823 涨到 2599，它拿着 9332 字原文是否

**测试**：901 项全绿（+2：`test_quota_weight_is_material_not_gist` 权重不跟摘要走、

> **本节结论已被 §17.19 修正（v0.24.0）。** 权重换对了函数，但**单位用错了**：`loc.chars`
> 是 `ingest.slice_by_anchor` 的 `len(body)`，即**原始字符数**（含标题行、排版符号、西文

### 17.18 收口：段系统提示词补上「段内同一件事只说一遍」（2026-09-19，v0.24.0）

**问题**：v0.23.0 卸掉了「逼它凑」的力（配额摊歪），但复读还有一半没堵——**禁重复的门
全开在「前文」这一侧**。

**盘一遍禁重复的条款，四处都是「与前文」**：

| # | 位置 | 原文 |
|---|---|---|
| ① | 本期计划块 `_episode_block` | 「把已经写过的句子或段落再写一遍来凑数是不允许的」 |
| ② | 段 user 提示词·凝缩要点栏 | 「已写正文里讲过的不要重复」 |
| ③ | 段 user 提示词·已写正文栏 | 「只供两件事：接住语气、不重复已写论断」 |
| ④ | 插入修补模板 `_INSERT_SYSTEM_TMPL` | 三反三正实例，判据是「并排放进听众耳朵里听一遍」 |

外加程序侧 `dedupe_script`（归一化后完全同字且 ≥12 字）。**五处管的都是「这一段与前面
写过的重复」。**

**漏的是什么**：第 2 期段 2 的复读形态不是这个——它在**本段内部**把前半段（第 91~106 句）
讲的事，到后半段（第 137~152 句）又讲一遍。写下第 137 句时，第 91 句还不是「已写正文」，
**五处一处也管不到**。段生成的系统提示词 `_segment_system_prompt` 里，一条防重复条款
都没有。

**定案：段系统提示词【生成要求】新增一条（第 5 条，原第 5 条顺延为第 6 条）。**

- 明确划界：这一条管「本段前后自我重复」，与「不重复已写正文」是**两件事，两条都要守**；
- **三反三正实例**：换词重说同一件事、同一条结论说两遍、换个包装重讲同一个例子 = 重复；
  补它能做什么/做不了什么、补结论成立的条件、落到具体场景与对象 = 不重复；
- 判据与④**同源**：「把本段前后两句并排放进听众耳朵里听一遍」——两处一个口径，不另立一套；
- **给退路**：挖不出新东西就往下挖一层（补条件、补代价、补反例、补具体场景），素材真用完
  宁可写短——**字数不达标可以接受，段内复读不允许**。与①同一口径。只堵不疏，它就会为
  凑配额回头重讲。

**明账（代价）**：段系统提示词 1605 → 2455 字符（+850）。它是每段的**硬开销**，计入
「可用 = 输入额度 − tok(系统提示词 + 已写正文全文 + 额外 + 400)」的扣除项，段能装的料
相应少一截。这是被卸掉「逼它凑」的力之后仍要付的钱。

**未跑一期验证**：这条改的是提示词，效果只能靠跑一期看。**测试**：902 项全绿（+1：
`test_segment_prompt_forbids_restating_inside_the_segment`）。

### 17.19 收口：配额权重的**单位**改正（原文有效字）+ 两轮提示词撤掉体量数字（2026-09-19，v0.24.0）

**问题一：v0.23.0 换对了函数，换错了单位。**

`loc.chars` 的出处是 `ingest.slice_by_anchor` 的 `{"chars": len(body)}`——**原始字符数**，
还含标题行。而成稿目标（6024 这一类）出自 `duration_model.chars_for_target`
（`时长 × 速度 × STANDARD_K`，`STANDARD_K` 的单位是**有效字/秒**）；地图压比
（`planner._ratio_issues`）也是拿期素材的**有效字**比成稿目标。配额要摊的是"这一段该写
多少**有效字**"，权重却给的是原始字符数——两把尺混用。

为什么这次混得看不出来：原始字符数与有效字的比值**逐节不同**（第 2 期：03 节 1.47、
04 节 2.04、05 节 1.88）——排版符号、西文、数字占的比重逐节不一样。于是"哪个节料多"
的排序都被带偏。

**三把尺，各归各的用途（定案）：**

| 量 | 出处 | 单位 | 归谁 |
|---|---|---|---|
| `chars` | `probe` 的 `effective_chars(body)` | 有效字 | **配额权重**（这一节能写出多少稿） |
| `loc.chars` / `len(compose)` | `ingest.slice_by_anchor` / 取料 | 原始字符数 | **装箱折 token**（这一节占多少输入） |
| `gist + points` | 凝缩产物 | 原始字符数 | 无用途，函数一并删除 |

**第 2 期实测（全篇目标 6024 有效字）：**

| 权重尺 | 段 1（第 03 节） | 段 2（第 04+05 节） | 段 1 压比 | 段 2 压比 |
|---|---|---|---|---|
| 摘要字数（v0.22.1 及以前） | 1823 | 4201 | 3.47 | **1.50 贴死下限** |
| 原始字符数（v0.23.0） | 2599 | 3425 | 2.44 | 1.83 |
| **原文有效字（v0.24.0）** | **3024** | **3000** | **2.09** | **2.09** |

整期压比 = 12611 / 6024 = 2.09。**只有按有效字摊，两段压比才同时等于整期口径**——
前两版都不是"某一段被压狠了"，而是"两段的压比不相等"。

**问题二：两轮提示词里的体量数字是多余的，而且有害。**

- **逻辑拆分**（`_logic_split_user`）：撤掉每节的「凝缩 N 字，原文 N 字」。分组只看语义，
  铁律自己写着「归类看内容，不看体量」，`_LOGIC_SPLIT_SCHEMA` 注释也写着"模型不产任何
  数字"——user 侧却先递了两个进去，自相矛盾。摆着字数会把模型往"按字数摊匀"上带。
- **规划轮**（`_segment_plan_user`）：撤掉「配额约 N 字」与每节的「凝缩 N 字」。这一轮
  段边界是程序定的、配额是程序摊的，它只写「期标题 + 段主旨」，字数只会把"这一段讲什么"
  带成"这一段该多长"。**「题目」这个叫法一并撤掉**——它产出的是**段主旨**，与期主旨同层级。
- **连带**：`_gist_chars` 的两处消费者都没了 → 函数删除（一个量没有用途就不该留在代码里）；
  `split_by_logic` / `_logic_split_user` / `_segment_plan_user` 的 `sec_chars`、`target_chars`
  参数随之取消；`_segment_plan_system` 里那条「某节的第 N 块」的说明是 v0.22.0 删块机制时
  的残留，一并删掉。
- **没动的**：本期计划块里的「**本期素材共约 N 字**」保留——那条是给**写作**模型的预算依据
  （素材撑不满目标字数时，它唯一能执行的出路是照实写短），且它本来就是有效字口径，
  与配额同一把尺。

**测试**：905 项全绿（+3：`TestPlanPromptHasNoNumbers` 三项；改写 -1 +2：
`test_quota_weight_is_material_words_not_gist` 三把尺对照、`test_missing_material_words_is_reported`、
`test_prompt_feeds_gist_but_no_size_numbers`）。

**未跑一期验证**：段 1 配额 3024 是否真写满，要跑一期看。
