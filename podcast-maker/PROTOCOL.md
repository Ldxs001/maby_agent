# PROTOCOL —— 播客制作智能体契约

本文件是该智能体的**行为契约**。任何改动先对照这里，再动代码。
契约五层，逐层收紧：身份决定能力，能力决定约束，约束决定接口，接口决定数据。

---

## L1 身份

**它是什么**

一台从素材到成品的流水线。输入一段文字（或文档），输出一集可以发布的播客：音频、视频、字幕、封面、图文。

**它不是什么**

- 不是创意生成器。脚本的**结构**由代码定死，模型只在给定结构里填内容。
- 不是视频编辑器。画面只提供固定档位，不做逐帧设计。
- 不是万能工具。缺 ffmpeg、缺字体、缺 LLM 后端，一律报错停下，不降级凑合。

**能力边界写在名字里**：`podcast-maker`，制作，不是创作，也不是编辑。

---

## L2 触发与能力

**触发方式**

| 方式 | 入口 |
|------|------|
| 界面 | `python main.py` 后操作四个标签页 |
| 命令行 | `main.py --check / --voices / --fonts / --continue <树根> --episode <期号>` |
| 代码 | `pipeline.run_episode(...)`、`pipeline.continue_episode(...)` |
| 服务 | `web_ui.run_server(host, port, pidfile)` |

**能做**

- 素材导入：`.md` / `.txt` / `.docx`，可按锚点切章。PDF 不支持：它是出版格式
  而非记录格式，章节层级只能反推，且其文本顺序是排版顺序而非阅读顺序
- 脚本生成：按风格预设与目标字数，调用 LLM 产出结构化对话脚本
- 时长换算：字数 ↔ 时长，单参数起步、三参数进阶、EMA 平滑
- 语音合成：本地 Qwen3-TTS 服务 / edge-tts，A/B 双音色，独立语速。
  本地引擎的起停由程序自理：开工前探活，没在线就地拉起，整期（整批）结束停掉并
  归还显存；别人起的服务不碰。合成前先腾显存（见 `tts.unload_llm_before_synth`）。
  本地引擎走 Base 变体，**音色跟着项目走**：项目缺角色档案时，在腾显存之后、
  逐句合成之前自动跑一次 `tts_service/make_voice.py`，用内置音色录一段参考音频
  落进项目的「音色」目录；整期所有句子都以它作音色源头，换项目互不影响，
  要与别的项目一致就用该工具的继承入口整目录复制。参考音频是项目资产而非过程
  件，落在项目根下，不参与过程目录的清理
- 音频后处理：拼接、降噪、片头尾、响度归一、BGM 混音（含人声闪避）、编码
- 字幕：中文避头尾断行、SRT / ASS / LRC、时间轴按实测校正（`.lrc` 供音频平台的歌词位）
- 画面：背景图、封面三尺寸、内置 BGM、四档动画、说话人指示层、视频合成；
  画面文字按实测宽度自动折行（含中文避头点），装不下就折、折到上限才缩字号，不裁字
- 产物校验：20 条门禁，输出可读报告

**不能做**

- 不能用 LLM 决定结构、字数、时长、断行位置——这些是确定性问题，归代码
- 不能在没有 LLM 的情况下生成脚本
- 不能在参数不可达时静默降级（如码率越界）
- 不能覆盖已有产物目录

## L3 行为约束

### 3.1 确定性特权

能用算法、正则、代码完成的环节，**必须**写进代码，不交给 LLM。

| 环节 | 归属 | 理由 |
|------|------|------|
| 字数统计 | 代码 | 计数是确定的 |
| 时长换算 | 代码 | 公式是确定的 |
| 断行位置 | 代码 | 禁则与宽度是确定的 |
| 时间轴 | 代码 | 由实测时长推导 |
| 文件命名与目录 | 代码 | 冲突判定是确定的 |
| 码率校验 | 代码 | 上限表是确定的 |
| 情绪标签 | LLM + 代码校验 | 模型选，代码查词表 |
| 句子内容 | LLM | 这是唯一真正需要模型的 |
| 语义检 | LLM | 判断依据在语义层：台词有没有编造素材外的东西，词汇匹配判不了（见 5.3）。**配置开关、默认关**——它是全链最贵的一项检查 |
| 承诺链检 | LLM | 开头开的那个口子收没收，判的是有没有被回应，不是字面有没有重现。**必检**；报出落点（承诺句 + 建议闭合位置），走与形式门禁同一条定点修路 |

渲染类操作同样如此：压暗、叠加、混合必须写在源像素所在的色彩域里。在带范围的
YUV 里叠一层黑色，亮度与色度会被分开处理，一次等比压暗就变成一次偏色——先转回
RGB 再叠，结果才与背景图、封面一致。

画面上的字印哪几行，也不靠人记。`assets_factory.FRAME_LINES` 是唯一一张清单，
一行一项，写明它**跟谁走**（全局 = 所有项目共用一份配置／项目 = 每个节目一套／
期 = 每一期都不同）、值从哪来、印在**封面**还是**背景**上。两张画面由同一个构造
函数 `frame_sequence(role, …)` 按这张表取件——从前封面与背景各写一份元素序列，
同一个元素在两处各描述一遍，改一处忘一处，两张画面就各印各的了。

分派的结果：

| 行 | 跟谁 | 封面 | 背景 |
|---|---|---|---|
| 品牌行 | 全局 | 印 | 印 |
| 主标题（节目名） | 项目 | 印 | 印 |
| 副标题 | 项目 | 印 | 印 |
| 标语 | 全局 | 印 | 印 |
| 版权行 | 全局 | 印 | 印 |
| 期标题 | 期 | — | 印 |
| 期数 | 期 | — | 印 |

**封面跟项目、不跟期，所以期标题与期数不进封面**；标语是整档节目的调性，两张画面
都印。字号也归这张表管：每行指定一个字号档，`FONT_SIZES` 再按画幅给出基准。

### 3.2 链是主体，模型只做两头

```
素材 ──[LLM]──▶ 结构化脚本 ──[代码]──▶ 音频/字幕/画面 ──[代码]──▶ 产物
  解析输入              确定性的中段                  组装输出
```

中段一旦出现模型调用，就是设计错误。模型只该出现在最左和最右。

### 3.3 统一推动点位

所有可调项集中在 `config_manager.py` 的四张表里，别处不得再定义：

| 表 | 内容 |
|----|------|
| `PARAM_SPEC` | 87 个配置项，含默认值、类型、值域、分组、阶段归属 |
| `MODE_SPEC` | 17 张档位表及其档位标签与说明 |
| `PRESET_SPEC` | 5 套风格预设 + 5 个风格维度 |
| `GATE_SPEC` | 20 条门禁的定义与级别 |
| `LAYOUT` | 排版间距与块顶位置，一律写成字号的倍数或画布比例 |

前端、CLI、管线全部读同一份数据。**新增一个可调项 = 往表里加一行**，不允许在业务代码里散落判断。
界面渲染只认 `params_payload()`：它按阶段归拢、按点位名前缀分区，界面照着渲染即可。
任何形式的「手工枚举某个 key 该放到哪个容器」都会漏——漏的那一项不会报错，只是永远空着。

判定标准：同一个量如果有两处独立来源，就是缺陷，不是风格问题。
本版的实例：项目设定覆盖配置的映射。

代码里读过的每一个点位都必须在 `PARAM_SPEC` 里声明。悄悄读一个没声明的点位，
取值永远落回默认值、界面上也没有控件去驱动它，症状只出现在产出的图上。
**读点位与总表必须对得上**，该约束由静态检查守着。同一份对账还管三件事：

- 每个点位都必须能在配置页找到入口
- 枚举档位的标签不得等于值本身（否则界面就是在显示英文裸值）
- 每个点位都必须有阶段归属，或显式声明为「仅配置页」

第 2 条尤其要紧：值是对的，所以功能测试全过，只有人读界面时才看得出来。

`LAYOUT` 里只有比例，没有绝对像素。曾经用「主标题位置加一百一十八像素」表示
标题下方框线的位置，字号一百零八的字实际高约一百三十，线落在字上。
这类缺陷调数值调不好：换字号、换字体、换画幅都会再次穿帮。所以要改的是表达方式，
不是那个数字。**间距只能取自 `LAYOUT`，序列里禁止就地写数值**，该约束有测试守着。

文字块顶边钉在画布高度的固定比例上。块内元素按实测包围盒往下推，声波跟着块底走。
主标题在任何一集、任何画幅里都落在同一高度——若改成按可用区居中，块顶会随行数浮动，
同一档节目每集都不一样高，横竖屏还会各挪一次。

画面上的字谁大谁小同样是**不变式，不是手感调参**。自上而下的层级固定为
**主标题（节目名）＞ 副标题 ＞ 期标题 ＞ 期数 ＞ 标语 ＞ 版权行**。
最大的一档给节目名、不给期标题：播客卖的是系列品牌，不是这一期讲什么；期标题字数
不定，长起来在最大档只能折行，一期一个样。字号表按**角色**命名（`hero` / `second` /
`episode`），不按位置——按位置命名（`f_big` / `f_mid`）在主标题换成节目名之后就没
人认得了。「主标题必须是最大的一行」有测试守着；这一条被改回去，画面上只是「又变丑
了」，没有任何一处会报错。

同一档字号在两张画面上各给一个基准（`FONT_SIZES` 每行是一对「封面基准 / 背景基准」）。
两张画面的骨架本来就不同：背景顶部对齐、块底留给三条声波，封面整块纵向居中——同一个
数字摆在这两种骨架里看上去不是同一个大小。印哪几行由 `FRAME_LINES` 分派（见 3.1）。

### 3.3.1 提示词的分类与分块

一个推进点位牵扯的资料不止一种：要处理的正文、判断用的参考、上一步的产物，以及
这一步当前该产出什么。全堆在一起，模型只能靠语序猜哪块是依据、哪块是要它交的东西。
所以**每一块都自带名字与用途**：块名用【】框起，括注说清它怎么用。

约定三条：

- 块名说「这是什么」（【素材】【已有计划】【待审脚本】），括注说「怎么用」
  （「判断依据」「当前任务：按这里逐条改」）。两者都不许省。
- **当前任务永远显式标出**。风格、背景、参考这类块在括注里写明「以当前任务为准」——
  它们与具体内容无关，冲突时让位的必须是它们。
- 长文本块（原文、素材）放最后。放前面会把指令挤到提示词的尾巴上，而那正是注意力
  最薄的一段。

七个点位各做什么、块怎么分：

| # | 点位 | 位置 | 提示词分块 | 输出契约 |
|---|---|---|---|---|
| 1 | 探查（类型与层级） | `probe.classify` | 【稿件结构】【各层按文体真正要凝缩的条数】【可选素材类型与各自的文体判据】【当前任务：判断三件事】 | `PROBE_SCHEMA` |
| 2 | 凝缩（单元逻辑骨架） | `probe._condense_prompt` | 【凝缩依据】【要做到什么程度】【输出】【本节原文】 | `CONDENSE_SCHEMA` |
| 3 | 排图（合并与切分） | `planner._map_prompt` | 【结构单元清单】【期数】【文体依据】【当前任务：分组】【另外给一项：受众】【每期给四项】【上一版的问题（体检重排时才给）】【输出】 | `MAP_SCHEMA` |
| 4 | 插期（定锚点与分组建期） | `planner._insert_prompt` | 【已有计划】【新素材的凝缩单元清单】【文体依据】【当前任务：定插入点并在锚点下分组建期】【输出】 | `INSERT_SCHEMA` |
| 5 | 写作（整篇脚本） | `script_engine.build_system_prompt` / `build_user_prompt` | system：【片头片尾】【输出格式】【当前任务：生成要求】【风格倾向】【两位主持人】；user：【补充说明】【素材】【上一版正文】【要改的地方】 | `script_schema(level)` |
| 6 | 内容检（语义 / 承诺链） | `script_engine.check6_llm` | 【本期计划】【各节凝缩】【素材节选】【待审脚本】 | `check6_schema()` |
| 7 | 定点修补（只改点名句） | `script_engine.build_patch_prompt` | 【本期计划】【各节凝缩】【素材】【要改的地方】【相关段落】 | `patch_schema(level)` |
| 8 | 段内补字数（只加新句） | `script_engine.build_insert_prompt` | 【素材】【本段已有正文】【任务】【怎么补】 | `insert_schema(level, need, cfg)` |
| 9 | 段内压字数（只改和删） | `script_engine.build_trim_prompt` | 【本段正文】【任务】 | `trim_schema(level, n_lines)` |

**契约由函数生成的有五条**，都是「要按当轮输入收窄、常量写不死」的：内容检按本轮判哪
几项收窄 `required`（`check6_schema(dims)`）；写作、定点修补、段内补字数、段内压字数按
情绪档位收窄 `emotion` 的 `enum`（`script_schema(level)` / `patch_schema(level)` /
`insert_schema` / `trim_schema`），后两条还要按「本次补多少字 / 本段共几句」现算数组
上限。其余四条是模块级常量。

契约一律走约束解码（`json_schema=`），内容检也算在内——它的落点三件套（第几句 /
原话 / 什么问题）是定点修补的入口，**能定点靠的是结构上必须给，不是求模型给**。

命名统一：提示词常量与契约常量都是公开名（`PROBE_SYSTEM` / `CONDENSE_SCHEMA` …），
不带前导下划线；只有模块内部的辅助函数才用下划线。

### 3.3.2 三把尺各管各的：画地图 / 单次调用 / 划分段

**「能喂多少字」里面藏着两个不同的问题**，从前用一个数兼两件事——于是两个不同单位的
数被拿来做减法、再比大小：一期 6.4 万字符的技术文档在「朗读字数」那把尺下压比合格，
到写作侧被判「超出容量」，原文一个字没进提示词。现在拆成三层，各用各的尺：

| 层 | 回答什么 | 尺 | 不合格怎么办 |
|---|---|---|---|
| **画地图** | 这一期该讲多少料 | 压比 / 朗读字数（汉字 1、标点 0.5、西文按词 1.5、符号 0） | 重排；两轮仍超则报错要求拆期 |
| **单次调用** | 这一次能装多少 | **token**：输入额度 = 最大输出 × `llm.input_ratio` | 调倍率，或回地图拆期（后端窗口由你自己开，程序不探也不管） |
| **划分段** | 这些料要分几次喂完 | 装箱（纯算术） | **多切一块，绝不丢原文** |

**素材能喂多少字由输入额度算出来，不由某个常数定**。从前内容检与定点修补都把素材
截到前 6000 字（`material[:6000]`）：生产里一期素材约 2 万字，只喂进 30%；探针
那份 27 万字，只喂进 2%。落在后面的依据一律被记成「素材里没有」，语义检于是把
本来正确的句子判成编造，再交给定点修补把它改坏。这种害处是静默的——它不报错。

两把尺怎么算：

- **画地图那把尺（内容额度，只在图上用）**：`script_engine.material_capacity`
  = 成稿目标 × 偏移量 1.25 × 压缩档（`probe.offset_chars` 收拢公共因子）。
  口径：**1 = 成稿目标**（每期时长 × 标准语速，**不含偏移**——它对应人设定的
  时长换算出的真实字数），偏移量 1.25 只进 x 与下限的算式、不改变"1"。它判的
  是「这一期该讲多少料」，不合格要拆期。
  **这个数字可以往下透传，但只当换算用**：透传下去的是「本期成稿目标字数」，
  拿去摊段配额；**它不参与「这次装不装得下」的判断**。倍率调大调小，地图一个
  字节不动；改时长改档位，倍率也不用动——两把尺互不干涉。
- **单次调用那把尺（输入额度）**：`llm_client.input_budget_tokens`
  = `llm.max_tokens` × `llm.input_ratio`。**单位只有一个：token**——原文（字符）
  折 token 后再与额度同单位比较，绝不拿一个的容量去减另一个的占位。
  折合比不写死：由后端回传的真实 `usage.prompt_tokens` 反标（`tokens_per_char`，
  取中位数），没有样本时按 1 字 = 1 token（最保守的那个值）。
  折算成 token 是客户端唯一的活（`material_tokens`）：字数 × 折合比 + 估算余量
  （8%，下限 1024）。余量按 8% 而不是更小：折合比取中位数，单次内容不同会有波动，
  实测同一份素材的两次调用比值差约 5%（0.55 与 0.58）——余量留 5% 时已被吃到只剩 3%。
  **折算只准偏保守**：估高了浪费额度，估低了直接顶爆后端。
- **后端窗口不归程序管**：它有多大是使用者自己的事，够不够自己调——程序既不探
  也不猜，更不对它提要求。任务开始时 `quota_note` 只报**准备喂多少**：「单次输入
  额度 N token（= 最大输出 X × 输入倍率 r）；本次素材 M 字折合输入约 K token。
  放不下时按节切成多段分别喂完（不丢料）」。放不下不叫「窗口不够」，叫「切开喂」。
  「配置 0 = 自动探测 → 探不到兜底 32768」早已删净，`required_context`（算窗口
  要求）这一版也删了，**不猜、不探、不兜底、不管**。
- 提示词模板占的字符数由调用方**拼完提示词之后**量出再扣：先拼后算，扣掉的才是
  这次调用真实的余量，而不是一个拍出来的常数。
- 实测：提示词 21049 字对应 `prompt_tokens` 11575，折合比 0.55。从 1.0 起步、随真实
  用量收敛，比写死 0.75 这类经验值稳——中文、数字、标点、表格线的折合比差得远，
  一个常数要么白砍素材，要么把请求顶爆。

放不下怎么办——**切段，不是砍料**：

- **写作按输入额度装箱**（见 3.3.4）：先由模型按内容把节分组成**逻辑段**（哪几节
  讲的是同一件事），再让桶**逐个逻辑段**过输入额度——装得下就是一段、装不下在组内
  按**整节**切成几段、单个节自己就超额度则报错。段内若仍装不下（折算比有波动、或
  已写正文比配额长了一截），把那几节**按整节分成几批**喂完——**不丢原文、也不换成
  凝缩**。装箱覆盖不到的边角才退到有损降级：
  可用额度已 ≤ 0、或拿不到逐节原文时，退到凝缩（每节逻辑骨架）顶替；连凝缩都没有
  （逐期即兴没排过图）才按额度截原文。两者都是**有损的，日志与素材头部都要把话
  说出来**。
- **内容检分批**（`check6_llm`）：核对本就是逐句的事，天然可切。每批能装多少由
  **输入额度**折回来（`budget_chars_for_check`），扣掉每批必带的那几样（系统提示词、
  整篇脚本、判据包、固定说明）——**这里不问「该讲多少料」**，那是画地图那把尺的事。
  按这个额度切段，相邻两批尾首重叠 1000 字（批小的时候压到批量的四分之一，免得步子
  被重叠挤成 0）；每批带**整篇脚本**——脚本不切片，句与素材段之间没有可靠映射，硬切
  只会制造新误判。合并规则只有一句：**同一句要在每一批里都被报出来，才算真问题**。
  某句的依据只落在某一批里，那一批当然找不到它，撤销它才是对的；「每一批都找不到」
  才等价于「全文里找不到」。撤销与未判定都要在结论里留痕，否则「这一轮问题变少」会
  变成一件没来由的事。
- 批数上限 8（`CHECK6_MAX_BATCHES`）：超限不静默降级，判「未核」交人工——把没核
  的那部分记成核过且没问题，比不核更坏。输入额度被模板吃光（`budget_chars_for_check`
  返回 0）同理，报出来的话要说清是「最大输出 × 输入倍率」这个旋钮不够。

判据分两块，各管一项（`_evidence_block`）：

- **事实判据**看【素材节选】：台词里的事实、数据、来源能不能在这里找到。
- **方向判据**看【本期计划】【各节凝缩】：本期该讲的讲到没有、正文开头抛出的设问收了没有
  （判据是「正文开头」，不是「片头」——片头尾不在这份稿子里，**全稿格式收束之后、整期定稿那一刻**才粘上去）。
  原文字面上没有「本期主旨」这句话，主旨是从原文得出的结论——拿结论核方向比拿几万
  字原文更直接，也不占预算。两样都由排图那一步产出、与写作同源
  （`pipeline.evidence_pack`），不另立第二个「本期讲什么」。

### 3.3.3 情绪档位：写与说两头同源

范式卡上有一项 `emotion_level`，取值两档（`paradigms.EMOTION_LEVELS`）：

| 档位 | 写脚本这一头 | 合成这一头 |
|------|--------------|------------|
| `none` | `emotion` 只填语篇功能标签（开场/追问/解释…）或「平静」，不填心情词 | 不拼语气短语（这一档本就不会出现真情绪） |
| `light` | 可以填心情词，幅度收在「略带」 | 拼「用略带X的语气说」 |

**一个值驱动两头，不许各取一次。** 写脚本按它决定字段能填什么，合成按它决定拼
不拼措辞；两头各读一次卡、或者一边读卡一边读配置，就会出现「稿子按略写、声音
按不贴说」——这正是要避免的那类不一致。取值的唯一入口是 `emotion_level_of()`，
合成那条链路把它从范式卡原样透传（`synthesize(emotion_level=…)` → 服务端措辞表）。

**为什么只有两档。** 实测：同一批台词贴「略」能把句与句之间的起伏收窄约一半，
代价是整体被压低约一成七；而「明显/非常」方向会反转——同一个「非常感慨」在肯定
句上抬高起伏、在中性句上又压低，与「明显」语义几乎一样效果差七倍。方向不稳的
档位不进产品。默认 `none`：文本本身平直时，压了就是把水搅死。

**档位与基调谁说了算。** 卡上的 `emotion` 基调是给模型看的**形容词**（"起伏允许
比论述类大""始终低一档"），档位是**硬约束**（字段能填什么）。两者由 `script_block`
一并写进【文体依据】，并明说冲突时以档位为准。另外，`none` 档的卡片基调里不许点名
心情词（有测试看守）：基调点名了、档位又说不写，模型只会照基调填，然后被门禁一条条
抓回来——两头打架，白跑几轮定点修补。

**档位同时管风格倾向里的「情绪密度」。** 那一维的合法取值取决于档位：`none` 档能填的
只剩语篇标签与「平静」，所以它说的是**功能标签怎么分布**（表头也换成「标签分布」），
`light` 档才说情绪起伏多大。同一个旋钮两套话术——两套并排写进同一份提示词，就是同一个
字段上一边禁止填、一边要求填，模型只能二选一，档位等于作废。其余四维（体裁、提问频率、
比喻密度、互动词强度）与档位无关，不跟着变。

**档位同时落在约束解码上。** 提示词里的 `emotion` 枚举按档位列，schema 的 `enum` 也按
档位收窄（`script_schema` / `patch_schema`）：`none` 档的心情词根本不在枚举里，模型当场
填不出来，而不是等它填完再由门禁抓回来。两条产出 `emotion` 的路都要收——只收整篇生成、
不收定点修补，等于给档位留一道后门。

**门禁 `emotion_level`（fail）。** 与 `emotion_vocab`（词表越界，warn）分开判：
前者是"标签合法，但这档不让写"，后者是"填了个不存在的标签"，要改的地方不同。
「平静」计在 `none` 档的合法集合里——它是默认底色、也是归一化越界值的落点；
不许它，归一化把越界值改成「平静」之后又会被判越界，那一句就卡死了、改不动。
越界明细带句号，定点修补接得上（`emotion` 本来就在补丁契约里）。

### 3.3.4 分段生成：字数核账的闭环

**整篇一次生成治不了字数漂移**。模型写作时没有全局计数器，「约 6024 字 / 335 句」
只是软引导——实测同一管线一期写出目标 4 倍（+289%）、另一期只写出六成（−38.6%），
双向都漂。分段生成（**成稿规划「mapped」项目走的就是这条路**；逐期即兴与单集当场
给料、出完即止，没有凝缩可分，走整篇；mapped 万一本期凝缩读不出来，也自动退回整篇）
把一次性大赌注换成小步闭环：

- **段边界分两步走，各有各的判据**：

  **第一步，逻辑拆分**（`split_by_logic`）：模型按**内容**把节分组成段——讲同一件事的
  归到一段，话题转折处断开。它只回**节序号**，不回标题、不回段主旨、不回任何数字；
  递给它的【节清单】也**只给「节号 + 标题 + 凝缩」，一个体量数字都不给**——分组只看
  语义，摆着字数会把模型往"按字数摊匀"上带（铁律自己写着「归类看内容，不看体量」，
  schema 注释也写着"模型不产任何数字"，user 侧从前却递了两个进去，自相矛盾）。
  分组要过三道归一（`_clean_logic_groups`，与排图的 `_clean_groups` 同一套口径）：
  越界与重复的序号丢掉并记下 → 组内按序号升序、组间按各组首序号排序 →
  没被提到的节**补成独立一段**。最后一条不能省：漏掉的节不是"少讲一点"，是那一节
  从此不在任何一段里，而清单看上去完整。两次都答不出合法分组就退回**一节一段**。

  **第二步，逐段过桶**（`pack_segments`，纯算术）：桶**逐个逻辑段**过一遍，桶容量 =
  输入额度 − 提示词 − 固定占位 − **已写正文**（前面各段的成稿配额；**逐段递减**——
  写过的正文要一直带着防断链，它涨一截，能装原文的地方就少一截）。一个逻辑段装得下
  → 它就是**一个写作段**；装不下 → **在它内部**按整节贪心切成几个写作段；两个逻辑段
  之间是话题转折，它们的节**不许**被装进同一个写作段。**写作段数 ≥ 逻辑段数**——
  日志那行「N 个逻辑段 → M 个写作段」说的是两个不同的数：逻辑段是模型按**内容**分的组，
  写作段是真正分别喂给模型的段。**切分单位只有一个：整节凝缩**——
  单个节自己就超桶容量时**报错**（要求调大 `llm.input_ratio` 或回地图拆期），
  绝不再从节中间切开：半个节取不出原文（`source_store.compose` 一次只认一个落点），
  也算不出账。同理，按字符位置切块与"一段最多合 3 节"两条旧上限一并撤销——
  合并与否由逻辑拆分定，段长由额度管，再拿常数去卡它等于把语义边界交回算术。

  **量不出 token 的后端不装箱，但分组照用**（`_groups_asis`）：没有重量只能说明"装不装
  得下"判不了，不能说明"这几节是一件事"不成立——照逻辑分组直接落段即可；确实没有
  分组信息（逻辑拆分也答不出）时才退成一节一段。

  配额先摊到**节**（`q_i = 目标 × 原文有效字权重 / Σ权重`，余数补给最大的一节），段配额
  **= 段内各节配额之和**，段 token = 段内各节 token 之和，段原文 = 段内各节原文按序拼
  ——**全是加法，没有除法**。从前那个「块配额 = 整节配额 × 块字符 / 整节字符」的除法
  连同它的误差一起消失：配额一把尺、内容另一把尺，两边不同源，数字必然对不上。

  **权重是「这一节的原文有效字」（`_material_chars` 读的 `chars`）** ——单位必须与成稿
  目标同源。同源这件事是可核的：成稿目标出自 `duration_model.chars_for_target`
  （`时长 × 速度 × STANDARD_K`，而 `STANDARD_K` 的单位是**有效字/秒**），地图压比
  （`planner._ratio_issues`）也拿期的有效字比成稿目标。三处同一把尺，摊出来的配额才和
  压比可比。

  另外两个数各有各的用途，都不是产能：

  | 量 | 单位 | 归谁 |
  |---|---|---|
  | `chars`（节的原文有效字） | 有效字 | **配额权重**（这一节能写出多少稿） |
  | `loc.chars` / `len(compose)` | 原始字符数 | **装箱折 token**（这一节占多少输入） |
  | `gist + points` | 原始字符数 | 只描述摘要写得多详略（**已无消费者**） |

  用错尺的后果是同一件事：那一节被派了它写不出的字数，只能把自己刚写过的话换个说法
  再讲一遍。第 2 期实测——按摘要字数摊，段 2 被多派 776 字、压比压到 1.50 贴死下限，
  去重删掉 64 句；改按原始字符数（`loc.chars`）摊，仍不齐（段 1 压比 2.44 / 段 2 1.83
  ——原始字符里排版符号与西文数字占的比重逐节不同，04 节最高）；**只有按有效字摊，
  两段压比才同时等于整期的 2.09**。`chars` 缺失时**报错**，不退回别的尺：退回去等于把
  摊歪的配额重新摊一遍，而且从日志上看不出来用的是哪把尺。
- **规划轮只做两件事：起标题、给每段写一句段主旨**。段数已由逻辑拆分与装箱钉死
  （schema 的 `minItems == maxItems == 段数`），模型既不能增也不能删。段主旨**只写
  「这一段讲什么」**，不许写"从哪里起、到哪里止"——取材范围由程序给死（第几节），
  模型手里没有的东西，写进段主旨它也写不出来，两套说法必然打架。**这一轮也不看字数**：
  段边界是程序定的、配额是程序摊的，把「配额约 N 字」「凝缩 N 字」摆进来，只会把
  "这一段讲什么"带成"这一段该多长"。程序只认
  `topics` 条数 == 段数；反复不过就按各段首节的凝缩主旨代填，**段边界与配额一个字
  不动**（这是从前「按一节一段硬分」的位置——现在段边界根本不挂在规划轮上）。
  「同一节进了两个段就打回」那条旧校验随之失效：切分单位是整节，一节只可能落在一段里，
  它本来就是旧分工的残留。

  从前不许模型在规划轮里分组，理由是「两边都去定边界，边界就不存在」。那条理由只在
  「分组与装箱并存」时成立；现在装箱不再定边界、降级成容量校验，边界只有一个来源，
  前提消失了。
- **账本单位只有字**。段字数配额 = 目标字数 × 各节原文有效字占比（程序算，合计精确
  等于目标）。配额是**按料摊的**，料少的段配额就该少。另有一道**配额地板**只防提示词
  自相矛盾：「约 N 句」带软句数下限，配额低于「N 句 × 每句最少字」时它就在说做不到的
  话，地板取这条线（默认 15 × 8 = 120 字），**不是碎段合并那把乘以期望句长的产能尺**；
  地板真咬到时，抬出的那点从最大的一段扣回，合计仍咬住目标。句数只在提示词里当形态
  引导（软句数 = 配额 ÷ 期望句长，期望句长取句长
  区间中点），**永不进核账**——句是离散量，小数目下百分比容差不成立（15 句的 5%
  是 0.75 句），字是连续量，与终点（1500 秒）同口径。句数的另一个去处是 schema 的
  失控刹车（防约束解码下无限写），按本段配额现算（配额 × (1+容差) ÷ 最短句），
  也不参与核算。
- **段写完，程序数实际字数**。容差 = max(配额 × 15%, 配额地板 × 15%)——比例与地板取大，
  和总时长门禁同一把尺。**下限是那根地板的派生量**（本机 120 × 15% = 18 字），不另立一个数：
  全篇各段容差之和因此恰是 15% × 全篇配额（配额本身低于地板的段除外）。超差**不重写整段、
  也不改已有句子**，按字数增删：**少了新增句子插进去**（`apply_insert`，已有句子一个字不动）
  ——补多少字由程序算，插在哪几处、插几句、每句多长全由模型按素材和上下文定，所以**带素材**
  （新增的每一句都得有出处）；**多了压紧措辞或整句拿掉**（`apply_trim`，只改和删、不许新增），
  **不带素材**（要减的话都在草稿里，递素材进去会让它把刚删的内容换个说法搬回来）。
  这两条路的**落地校验都不判句长**（v0.36.0 起）：句长是**全篇一把尺**的量，归门禁
  `line_length` 判、两个方向都有处方；写作阶段替它把关，代价是把「一条坏句」放大成
  「整段停摆」（真机一条 7 字句让 40+ 条新增整批作废，那一段的缺口 1872 字一轮都没再试）。
  **落地失败也不收工**：这一轮作废（稿子一字不动）、轮次照减，跑满
  `script.segment_fix_rounds`（默认 5）才取最接近配额的一版收尾。差额按比例滚入后面各段的
  配额，误差逐段吸收，总账始终咬住目标。
  - **轮次顺序：第一轮「写作 + 计算」，之后每轮「补字 → 查重 → 替换 → 计算」**（v0.37.0）。
    「计算」挪到**轮末**是本轮收口，差额供下一轮开头补字用。补字是复读的源头——补完立刻查、
    就地换，替换完再核账。轮次预算仍吃 `script.segment_fix_rounds`，不新增配置点。
  - **查重与替换（v0.37.0）：判重范围整篇，动刀范围本段。** `find_repeats` 输入整篇句列表与
    本段句号区间，只报**本段内、后出现**的副本（每组留第一次出现，其余每一处进名单）——
    「段 2 复读段 1」这种，只有整篇范围看得见；判重口径复用 `_dedupe_key` 与 `DEDUPE_MIN_CHARS`，
    与整期兜底同一把尺。`apply_replace` 落地换成新句，**行数一个字不变**（没有 `absorb`、没有
    `inserts`），四条缺一即拒：只动点名的句子；新句归一化后不得与整篇任何其它一句重复；
    新句字数落在**被替换那句的原字数与单句上限之间**（换短了核账又报缺口，下一轮又补、又可能
    复读，绕回老路）；带 `emotion` 时须在语篇词表内。替换提示词要看得到**全篇已写脚本**——
    问题虽然发生在本段、原文素材也只给本段，但【本段原文】（素材）与【已写脚本】（全篇正文，
    逐句带编号）分开摆，再给【要换掉的那句】与【这一处的任务】。防重复那套正反例抽成共享块
    `_norepeat_block()`，插入与替换一份纪律两处用。
  - **补字轮同样要看全篇已写正文（v0.37.0）。** 首写轮本来就拿着全篇已写正文，补字轮原先只有
    本段那三块——提示词却要它「到素材里挑正文还没讲到的点」，它看不见前几段讲了什么，必然撞
    上去（第 2 期 33 句逐字复读就是这么来的）。`build_insert_prompt` 补齐前文块，两路视野对齐。
    同时 `insert_system` 把口径从「复读不算补字」改成**禁令**「禁止重复已有的脚本内容」，
    并删掉那句等于明许重讲的后门「挑不出新东西时，把已经提到的点讲得更细」。
  - 为什么补字数不靠「把现有句子改长」：单句有 8~40 字门禁，补长的天花板 = 句数 ×
    （上限 − 现有句长）。实测缺口 628 字时，46 句 × 13.7 字余量 = 629 字，天花板正好
    被顶满——每一句都被点名，形式上补丁、效果上等于整段重打，而模型实际只补进 24%。
    插入没有天花板。改已有句子是**门禁那条路**的事（`patch_schema` 只许替换、行数不变），
    别与这里的按字数增删混为一谈。插入进来的句子同样要过 8~40 这道门禁，只是**不在落地时
    判**——它写完就进稿，句长由门禁那一轮报出来、走定点修补。定点修补的文本字段另外带一个
    **最小长度**（`minLength = gate.min_chars`）：它在门禁与检查阶段跑、改完直接落盘，一个
    残句没有下一道工序替它兜；**只加下限、不加上限**（实测后端对 `maxLength` 是硬截断）。
  - **补字的质与量一起管，不许用重复凑数。** 只报「少 N 字」等于只给量的目标，而凑字数
    最省力的路径就是**换个说法把说过的话重说一遍**：不踩「不许编造」、字数还随便控。
    所以铁律里写明三条——不许同义重述（判据看**意思**不看措辞）、每句必须带进正文里
    还没有的信息点（素材里有而正文没讲的优先）、多处插入彼此也不许重复；用户提示词
    再把排重排成显式步骤（先列已讲要点 → 从素材挑没讲到的点 → 写句 → 逐句回对）。
    **出口只有「讲细」，没有「少补」**：允许少补就等于允许一句不补，字数目标会整个失效。
  - **「不许重复」必须配正反例，不能只给一个名词。** 只写一句「意思一样就算重复」，
    模型拿它对照自己刚写的句子，永远判自己合格——判「意思重不重复」的人和被管的人是
    同一个。所以提示词里**算重复**与**不算重复**各摆三条实例：
    算重复的是「换个词问同一件事」（"性能开销会不会显著增加" vs "性能开销会不会突破
    可接受范围"）、「换个词答同一件事」、「前一句还没答，后一句就替它下结论」；
    不算重复的是「背景相同但问的是另一件事」「同一件事补上了新的细节」「同一个点把
    另一条分支补上」。例子之后收成一句可用的判据：并排放进听众耳朵里听一遍，听到
    「同一件事又说了一遍」就是重复——**换个说法不改变这个判断**。
    同时收紧「一个信息点可以拆成问答两句」那道口子：改成「一个点写成一句就够，
    最多一组一问一答」——允许"两句"等于允许扩张成两问一答拿它凑字数。
  - 程序侧只能兜住**一字不差**的重复：`dedupe_script` 的判据是归一化（去空白与标点）后
    完全同字、且 **≥12 字**，措辞相近的拦不住（那是改写，得靠上面那三条提示词纪律）。
    12 字这个门槛还漏着一段：8~11 字的完全重复句够不着它，会直接进成片。
  - **段内自重复是另一道门，不许拿「与前文查重」当已覆盖。** 上面那三条纪律、连同程序侧
    `dedupe_script`，管的都是「这一段与**前面**写过的重复」。第 2 期段 2 的病不在这儿：
    它在**本段内部**把前半段讲的事，到后半段又讲了一遍——写下后半段那句的时候，前半段
    那句还不是「已写正文」，几道门一道也管不到。所以段生成的**系统**提示词【生成要求】
    里单列一条：本段自己内部同一件事只说一遍，配三反三正实例，判据与补字提示词同源
    （「并排放进听众耳朵里听一遍」），并给足退路——**字数不达标可以接受，段内复读
    不允许**。退路必须给：只堵不疏，它就会为了凑配额回头把说过的话重讲一遍。
- **逐段上下文**：每段带本期计划 + 本段覆盖的凝缩要点 + **本段那几节的原文**
  （恒为整节，按节号顺序拼；取料见 `pipeline.section_material_of`，没有半节）
  + 已写正文全文（只供接语气、查重，禁续写——整篇才 6000 字量级，全文喂得动）。
  **不再把整期素材过一遍闸门**——每段只喂本段那几节的原文；拿不到逐节原文时
  （还没排图、版本对不上）才退回整期素材，不让人卡在一步跑不动。同名标题会取错
  节，所以判据包组节时补回 `line` 消歧（`source_store.compose` 支持它）。
- **门禁与修补原样复用**：分段只替换「初稿怎么来」；拼装后照旧跑全部门禁、走定点
  修补（各段拼起来的是一份正文，与整篇路一样）。**片头尾不参与这一段**——它在所有
  检查都做完、整期定稿那一刻才粘上去（见 3.4）。每段写完即落盘，落的是**半期正文，
  不带片头尾**：粘上就成了「半期 + 片头 + 片尾」，片尾挂在半篇的末尾，形态像一整期、
  其实是残缺，真被中止时交到手上的就是这样一份。

### 3.4 前置规范大于后置验证

- 约束解码：脚本生成直接给 JSON Schema，而不是生成后用正则修补
- 硬约束要落在 schema 的 `enum` 上，不能只落在提示词与门禁上：情绪档位这类「不许填什么」
  的事，在枚举里去掉就是当场填不出来；等它填完再判、再定点修补，是拿一轮成本去买一件
  本来不该发生的事
- 格式收束：解析脚本时丢弃模型给的所有数字，重算
- **片头尾由代码在整期定稿那一刻粘上去**（`script_engine.glue_intro_outro`），模型只写正文。交给
  模型复述就必然措辞漂移，再拿门禁逐字验，写对了是运气、写错了白烧一轮重试。格式轴的事由代码办
- **粘在全稿格式收束之后，粘完只补时长**：正文那一遍格式收束（`normalize_script`）在粘合**之前**
  已经跑完；粘合自身只做两件事——按模板逐字拼出片头尾、给新粘的句子补 `estimated_seconds`（缺了
  它那几句就是 0 秒，字幕时间轴会错位、总时长少算，这是当初顺带跑一遍收束的唯一正当理由）。粘合
  **之后不再跑任何格式工序**：从前它尾巴上顺带再跑一遍全稿收束，那把尺子（语篇词表）会把片头尾的
  标签一律洗成中性档「承接」，片头因此丢掉「这是开场」这个位置信息（v0.34.6 改正）
- **片头尾与前期回顾的标签只归程序**：片头首句「开场」、前期回顾「回顾」、片尾「收束」，取自
  `config_manager.PROGRAM_ONLY_TAGS`——不发给模型（输出 schema 的枚举仍是语篇词表那八个词）、
  不进语篇词表。它们会被读到的场合有两处：① **脚本页的重判**（那条路读盘上成品整份、含片头尾），
  重判那一次把这三个词放行；② **脚本页的标签下拉**，选项＝语篇词表 ＋ `PROGRAM_ONLY_TAGS`
  ——盘上稿子里有这三个词、下拉里没有的话，那一格就没有任何选项能被选中，浏览器会退回显示第一项，
  **数据是对的、界面是错的**。正文的门槛一点没松：界面上能选出来的正文标签只有词表那八个，模型
  也产不出表外的值。
  **片头第二句挂的是词表内的中性档「承接」**——它是「接开场的话头，往下讲本期」，不是第二个开场；
  目标序列里只有一个开场（见下一条的四种序列）。
- **标签序列（片头档位 × 回顾开关，四种）**：

  | 片头档位 | 回顾 | 序列 |
  |---|---|---|
  | 标准（两句） | 开 | 开场／回顾／承接／正文…／收束 |
  | 标准（两句） | 关 | 开场／承接／正文…／收束 |
  | 简档（一句） | 开 | 开场／回顾／正文…／收束 |
  | 简档（一句） | 关 | 开场／正文…／收束 |

  **前期回顾的位置是第 2 句**（紧跟片头第一句，在片头其余句与正文之前），不分档位；它是「上期讲到
  哪儿」的交代，得在开场之后紧接着让人听到，摆到正文后面就成尾声了。
- **程序拼的文本自己合尺**：片头／回顾／片尾按设计粘在门禁之后，长度没有第二个人管——所以
  回顾在**拼出来那一刻**就按正文那把尺（`gate.max_chars`）切成若干句（`subtitle_engine.
  split_sentences`：只切标点、不切西文词、一个字不动），一条模板因此通常产出多句。2c / 2d 的
  回顾曾长成 195 / 241 字的「一句」，在歌词框里要排 7 / 9 行而框只有 8 行高，多出来的行被
  `\clip` 裁掉——不是难看，是丢字
- **粘合句不进任何逐句判据**：片头／回顾／片尾是程序逐字拼的固定结构，模型没参与、也改不动——
  判出来也没法定点修（修补是让模型改句子，改完就不是固定结构了）。所以 `gate_generate` 按标签
  认出它们（`emotion ∈ PROGRAM_ONLY_TAGS`）后，`line_length`／`line_duration`／`banned_words`／
  `readable_text`／`line_end_punct`／`emotion_vocab` 一律跳过，连说账上它们还充当**分隔符**（前后
  两段正文各算各的）。**整篇量照算**（句数、总时长）——粘合句确实存在、确实要念，报告里注明跳过
  了几句。生成过程里门禁本来也看不到它们（粘合在门禁之后），这一条主要作用于重判。
- **整期只粘一次，粘在定稿那一刻**：粘合挂在「这一期交出一份成品」这个点上（`generate._finish`），
  不是挂在「每写一次盘」上。片头尾不进轮——不参与生成、不过门禁、不被定点修补、不核字数，
  逐字拼出来的东西也就没有「模型照没照做」可验。于是：
  - **中间产物一律是裸正文**：分段生成的段间落盘落的是半期正文；整期稿子在门禁那几轮里落的也是
    当时那一版正文。中途被中止、进程被杀，手上那份如实是「写到这儿的正文」，不会伪装成一整期
    ——粘过的稿子形态像成品，混进中间产物里就再也分不出哪份写完、哪份没写完。
  - **定稿那一次粘，且只粘一次**：门禁过了从 `_finish` 定稿，轮次用尽从兜底出口定稿——改成功
    没改成功，交到手上的那一份都带片头尾。定稿这一份同时落盘（出片读的是盘上那份）与返回
    （界面拿的是返回值），两处共用同一个对象，**日志一行对一次粘合**。从前的毛病是「每轮落盘都
    粘 + 同一轮返回再粘一遍」，两轮跑下来日志冒三行「片头尾已粘上」，读的人分不清是粘重了还是
    落了几次盘。
- **是「粘」不是「替换」**：头加片头、尾加片尾，正文一句不动、一句不删。从前那版是拿片头句
  替换正文第 1 句、拿片尾句替换正文最后 1 句——句数不变，所以门禁看不出来（那条判据只验首末
  句像不像片头尾，必然通过），实际每期正文头尾各丢一句：第 2 句还在应答一句已经不存在的开场
  白（听感上就是「没错」开头），倒数第二句提的问题永远等不到回答。**凡「固定结构」与「模型
  产出」并存，只许加、不许盖。**
- **粘在所有门禁、内容检与定点修补之后**：模型、门禁、修补、字数核账看到的自始至终只有正文。
  片头尾不在这份稿子里，也就**不存在「它照没照做」这条判据**——留着只有两种下场：恒真（模型
  没参与），或拿正文去验首末句、每轮报「未命中」，然后让模型去改一句它从没写过的句子。缺料
  各退一步：受众缺 → 「，面向…的听众」那一小段消失；期标题缺 → 「本期讲述…」整句不粘。粘出
  半句话比少粘一句坏得多。**定稿**落盘与返回界面的都是**成品**（带片头尾），循环里自始至终拿
  正文那一份接着改（`_glued_draft` 复制一份出去，原稿不动）——定点修补按句号改句子，正文那一
  点句号不能被片头句整体顶偏两位。**唯一的例外是脚本页的重判**——它读的是盘上那份成品整份
  （片头尾已经在里面），所以只有那一次把片头尾的两个程序专用标签放行，判据本身一字未改
- 生成引导量与验收判据分开：提示词里的数字是引导，门禁里的数字是判据，**不要求模型自测它测不了的量**
- 可回灌修正的量必须放在生成阶段：放到末尾检查，等于放弃了唯一的修正机会
- 人定的量由代码持有：项目已定的总期数不以模型回填为准，它漏填或改口都不改变结果
- 门禁只要求「被要求产出的东西」：关掉视频开关后仍去要视频，等于让每一期都判不过
- 反馈必须可操作：给模型「还差 47 字」，而不是只给「偏差 -15.9%」
- 排版位置由实测包围盒推出，不靠猜。测得出包围盒，就不该估坐标
- 观感类的量也要写成不变式：三条声波「不相交」不是靠调间距试出来的，
  而是让相邻中线间距 = 振幅之和 + 留白，净空因而恒为 `留白 × 单位振幅`，与相位无关。
  能写成不变式的就不写成手感数值，并且要由测试量真正落笔的那条线

### 3.5 fail-closed

- 缺 LLM 后端 → 报错，不生成假脚本
- 缺字体 → 报错并列出候选，不用渲染不出中文的默认字体
- 字体缺字形 → 报错并指出具体字符，不画出豆腐块
- 缺 ffmpeg → 报错，不跳过合成
- 码率不可达 → 报错，不静默钳制
- 产物门禁不过 → 写 `blocked.lock.json` **留痕**，照常出片、照常记账：产物与报告都落了盘，
  要不要带着问题出片是人的选择（与脚本阶段同一条定调）。过没过写在报告里——清单的 `report`
  与 `报告/` 那一份，界面在历史列表上标出来
- 脚本门禁不过 → **不中断**。稿子与结论一起落盘，合成前提醒一次，改稿还是照出由人定。
  没稿子却要出片也不现写一份——那是脚本阶段的活，合成端只报错

**唯一的例外**：语义检与承诺链检里，**模型没给出结论**的那些项降级为「交人工复核」，
不阻断。注意区分两种情形：判为不通过的照常拦截并打回重写，只有「未判定」才走例外——
把「没检查」当成「检查通过」比不检更坏，报告上的绿灯会骗人。理由见 5.3。

### 3.6 锁文件与续跑

产物门禁不过时写 `<项目>/过程/<期号>/blocked.lock.json`（**留痕，不是闸门**——它不拦出片，
只用来记「哪一期、因为什么没全过」，`--continue` 靠它认期），记录：

```json
{"blocked_at": "render", "reason": "…", "context": {}, "attempts": 1, "time": "…"}
```

脚本阶段的结论不走锁文件，另落一份 `<项目>/过程/<期号>/gate.generate.json`——它是记录
不是闸门。合成前读它给人提个醒（只读、不判、不重算），确认与否都不影响能不能出片。
`blocked_at` 的 `generate` 取值因此成了历史遗留，只有 `render` 在用。

锁跟着期号走，不跟着目录走——产物按类归位之后，一期由「树根 + 期号」才定得下来。

续跑时读锁文件与已有产物，缺什么补什么，已有的一律复用。**不重跑、不覆盖、不猜测。**
「续哪一期」也是这条规矩的一部分：命令行没给期号时从锁文件反推，但只有恰好一期卡在
门禁上才自动定，零期或多期一律把选择权交回去。猜错的后果不是报错，是拿着另一期的
产物当这一期的接着做。

### 3.7 零文本痕迹

日志、变更日志、产物报告里不得出现内部实现细节与个人路径。配置快照写出前过滤 `llm.*` 与 `_*` 前缀。

### 3.8 批量的规矩

勾了几期就按顺序跑几期。四条约束，一条都不能松：

- **串行。** 语音合成与视频渲染吃满机器，两个一起跑只会互相拖慢，还可能爆显存。
  批量的价值在「不用守着」，不在「同时开工」。
- **单期失败跳过。** 二期挂了不该把三到八期一起赔进去——那些期跟它没关系。失败的
  期号与原因记进结果，使用者重勾一次就能补上。
- **连续同因失败到阈值就停。** 失败若是系统性的（模型后端挂了、合成服务没起），跳过
  等于把同一个错误重复 N 遍：几小时白等，机器还一直占着。所以按「同一个原因连续几期」
  计，不按总失败数——三到五期各栽在不同原因上，说明各有各的问题，要跑到底。
- **中止是软的。** 界面点「中止」只置一个标记，当前这一步做完就不再开新的一期。硬杀
  线程会把正写着的文件截断，半截的清单比没有更坏——它看着像做完了。

批量里每一期走的是**与单期同一条路径**（`_render_sync`），不是另写一份循环。两处各写
一份的话口径迟早漂开：单期读盘上的脚本、批量却在现生成之类，而两边单看都挑不出毛病。

**批量合成不生成脚本。** 读盘上没有这一期的脚本就报错，绝不顺手现生成：批量合成的意思
是「合成我已经定稿的那几期」，现场生成等于把审过的稿换成模型新写的另一份。

**门禁在前，不在后。** 合成页只列有脚本的期，所以「选了一期却没有脚本」这个状态在界面上
产生不了；接口层再挡一道，绕过界面直调也拦得住。不做事后补救。

### 4.1.1 项目登记接口

`planned_episodes=None` 表示交给模型规划；填了以人为准。`apply_to_config()` 是
**生成脚本与出片共用的唯一覆盖入口**：两处各写一份映射，迟早不一致——生成时按
项目节目名写片头句，出片时却按配置里那个（人根本填不动的）节目名出画面，同一期
就印出两个名字，而两处代码单看都挑不出毛病。三个通道键（`project.program_name` /
`project.subtitle` / `project.audience`）不在配置总表里，只在 `CONFIG_PASS_THROUGH` 里：
它们不由人配，值一律来自项目。

**存储分两处。** 登记表 `_projects.json` 只存身份与设定；地图存在项目目录里的
`地图/map.json`。两处都存就是两个真值来源——重排一次图要么漏写一处，要么两处都写、
写岔了谁也发现不了。所以读时把地图挂回内存（`item["map"]`），写时把它剥掉。

**产物在哪不靠记账记。** 早先每条地图条目记一个产物目录名，于是「目录名写错」和
「产物没出」在数据上长得一样。现在只记「出没出过」这一个布尔，具体路径由布局模块
按（项目, 期号）算出来。

登记表损坏时抛错而不是重建：重建等于清空全部期号记忆，而且没人会知道发生过。

**规划方式（`plan_mode`）在立项时定死**，三种取值回答同一个问题——本期素材从哪来、
要不要排图：`mapped`（成稿规划）、`episodic`（逐期即兴）、`single`（单集）。
它不在 `EDITABLE` 里，改它就是报错而不是静默忽略。唯一例外是 `legacy` ——本功能
上线前立的项目，落盘没有这个字段。它们是"还没选过"而不是"选了逐期即兴"，所以允许
补选一次，补选之后同样定死；替它们选掉，成稿规划这条路就再也走不上，而它们恰恰是
最想排地图的那些。

**单集也是一个项目。** `single` 与另两种并列，不是"不建项目"的第二条路：它同样有
节目名与副标题（画面靠它们印出主导行）、同样在登记表里、产物同样落在自己的项目目录。
受众这一项它没有——那一步跟着地图走，所以片头里「面向…的听众」那一小段自动消失
（不是缺陷：`{audience_clause}` 留空就整段不出现，欢迎语照旧完整，见 3.4）。
差别只有三条——不排图、计划期数恒为一期、出完即完结（`next_episode` 不再前进）。
从前它走的是"脚本页与合成页的下拉选「不归属项目」"，产物落到输出根下一个谁都不认识
的目录里等人认领，画面也就印不出节目名。两条线合一之后，流程只剩一条：立项 → 脚本
→ 合成，界面上不再出现"单集模式"这个入口。

**成稿规划排完图才算可选。** 料源由地图落点决定，没有地图就没有本期素材，所以未排图的
成稿规划项目不进可归属集：项目卡片上「设为当前」置灰，脚本页与合成页的下拉不列它。
判据与取料同源（前端 `planReady`、后端 `resolve_material`），不另立一套。

有地图时「下一期」由 `next_from_map()` 决定，不再靠 `bump_episode()`：分支期号夹在主期
之间，数字进位算不出来——`bump_episode("3a")` 得到 `"4a"`，把插进来的分支当成了新主线。

登记表结构变更（`STORE_VERSION`）只在读时补齐、不改写盘上旧文件，用户没动过的项目
不会被无故重写。

**入库即探查。** 素材一落盘就跑探查，结构与类型在那一步定下来并冻结：排图直接用
冻结结果，不必再等一次；排图失败（模型不可用、输出被截断）也不至于把探查一起赔进去。
已在库的素材走缓存，既不重扫也不重判；要重判由 `/api/source` 的 `scan` 动作触发。
探查结果的版本（`probe.IR_VERSION`）对不上时当"没探查过"重扫：字数口径换过一代，
混着用会把有子节的章节算小。

素材必须落盘：只活在界面内存里则刷新即失，项目也就无从记住"这一期讲的是哪一段"。

**画地图是「读结构 → 逐节凝缩 → 分组 → 取原文」四步，不是一次长调用。**

1. **结构从稿子里读出来**，不喂模型：`#`、`一、`、Word 标题样式各算一路证据，
   层级归一到 H1…Hn，同系列（`08a/08b/08c`）由编号族归纳。
2. **逐节凝缩**（`condense_units`）：一次调用只看一节原文，做的是**保逻辑的有损
   压缩**——留下这一节说清了什么、反对什么、有哪几条主线，以及跟着每条主线的细节
   区分。把全书押在一次输出上，模型面对几十万字只能按比例各切一刀，重点必然漂；
   逐个调用时上下文与输出都不随全书体量增长。凝缩结果写回 segment 并随探查结果
   落盘，重排一次图不重复烧调用。**凝缩失败即停下**——它是分组的依据，拿不到它
   排出来的图是按字数硬切的，那种图看着完整，才是最难的假成功。按哪种文体压，
   由范式卡的 `condense` 一项给出（见下文"凝缩规则与排图判据分开"）。
3. **分组交给模型**（`plan_map` 的一次调用）：给它的是一份凝缩清单（序号、标题、
   体量、主线、主干），要它回答"哪些序号合成一期、这一期叫什么、讲什么"。
   `_clean_groups()` 把回答归一成 1..n 的一个划分：越界与重复的序号丢弃、
   分组间顺序打结时按首个序号重排、**没被任何一期提到的单元补成独立一期**
   （漏掉的不是"少讲一点"，是那几节从此不在任何一期里，而地图看上去完整）。
4. **位置由代码填**：期号、每期体量、落点。落点是 `{source, anchor, line}` ——
   `line` 是标题所在行号，同名标题（各章都有一节「小结」是常态）靠它定到具体
   那一条；只按标题取，取到的是靠前那一条，而地图上写的是同一串字。
5. **受众也在这通电话里一并问掉**（`MAP_SCHEMA.audience`，与 `episodes` 同级、同样必填）：
   整档节目面向谁，一句话、≤12 字，写成能直接填进「面向___的听众」的定语。它落进
   **项目**、不进地图——受众是节目级（每期片头都印同一句），与期无关。重排地图不覆盖
   它（只认第一版），人填过更不覆盖（同 `planned_episodes`）。

**取原文不截断。** 生成某一期时按落点取回该期涵盖的**单元原文**（`compose`，
含子节），不做字数截断：一期的体量在排图那一步已按目标时长定过，取出来正好是
一期该有的量。目标字数由提示词给出，模型按它取舍——不预先砍料。

**凝缩是保逻辑的压缩，不是写摘要。** 摘要从一节里挑几条最重要的，压完只剩骨架的
骨架；而排图那一步**只看凝缩、不看原文**（`planner._units_text` 收的就是凝缩），
凝缩没留住的，后面永远补不回来。两节讲同一条论证链的不同环节，各自的摘要都写着
"讲了 X 的重要性"——模型就看不出它们该合；反过来两节都很泛，看着又像同题。所以：

- 提示词撤掉了"每条 40 字内"这类长度上限。40 字装不下一条带条件与反例的主干，
  写出来的只能是口号。**条数也不设上限**：有几条主干写几条，一条主干也不许拆成
  两条凑数。
- 提示词要求保住**该有的细节区分**：数字、条件、边界、前提、反例、结论的适用范围，
  跟着它所属的那条主线一起写进去。判断标准写在提示词里让模型自检——"把两节的凝缩
  放在一起，能不能看出它们是同一条链的两段，或者看出它们讲的是两件不同的事"。
- 提示词**给出一条完整的填充示例**（照抄格式就能对）。凝缩是**每个单元一次调用**，
  只有字段说明、没有示例时，格式上的偏差会被乘上单元数，而这一步失败是致命的。
- 单元清单里**一条不砍**。从前 `_units_text` 只取前 6 条主干、前 6 个概念——那是
  与提示词无关的第二道砍：凝缩留全了，排图也看不见。

**不替使用者决定要不要思考。** 用推理型模型还是普通模型由使用者自己定，凝缩这一步
**不传** `reasoning_effort` 这类字段。要保证的是**两种都跑得通**，这是客户端的事，
不是模型的事：

- 后端明确拒绝某个可选字段（HTTP 400/422）时逐个摘掉它重试，摘掉哪个标哪个
  （`meta.reasoning_dropped` / `meta.degraded`）。**两个字段不连坐**——为了摘掉一个
  而把另一个也牺牲掉，等于白丢一项能力还不吭声。
- 超时、5xx、连不上、返回非 JSON **不降级**。它们与字段无关，摘字段治不了，
  而把它们当成"这个字段后端不认"会在日志上写下一个假结论、把真实起因丢掉。
- 思考与答案混在同一个 `content` 里的后端也要接得住：剥掉成对的思考段，找 JSON 时
  **逐个花括号试解析并取最后一个成立的**（不是"第一个 `{` 到最后一个 `}`"，也不是
  第一个成功的——没带思考标记的后端，模型先想后答，第一个成功的多半是思考里的草稿）。
- 推理额度如实带回 `meta.reasoning_tokens`，凝缩日志里带「思考 N token」。要不要付
  这笔代价由使用者决定，但付了多少得看得见。

**代价按步算，都能看得见。** 逐单元凝缩是**每个单元一笔固定开销**（实测一段两行
原文默认 334 秒 / 3997 个推理 token），乘以单元数就是整轮的量级；类型判定的粒度决定
整张地图（同一份素材三次运行实测给出 H2 / H1 / H2，取料单元数随之在 5 与 3 之间跳），
每份素材只花一次，结果冻结落盘。**哪一步都不由程序去关思考**——那样等于替使用者选了
他要用的模型。

**凝缩结果带版本。** `probe.CONDENSE_VERSION` 随结果写进 segment，并由
`probe.stamp_condense()` 记到整份探查结果上（连同 `condense_model`）。提示词换过，
旧结果就是另一套标准下的产物；留着它，一张图上会混着两套标准排出来的期，而且从
界面上看不出来。版本对不上的凝缩结果按"没凝缩过"重做——与 `IR_VERSION` 对不上
就重扫是同一条规矩；`force` 仍可强制重凝缩。

**期数由合并与切分的结果决定，不是除法算出来的。** 排图那一步把凝缩之后的单元
按文体与章节上下分组——**分出几组就是几期**。`probe.capacity()` 回答的是「一期装得下
多少**原文**」：成稿目标字数（目标时长 × 语速）乘压缩档（`script.compress_ratio`，
1:3 / 1:5 / 1:10，默认 1:5——写作 1:5，意思是 5 份原文压成 1 份成稿）。这个口径三处
共用：给 `pick_units` 定下钻参照、给排图当每期分量参照、给体检当判定分母——**不是**
拿它除总字数去定期数。从前这里做过 1:1 的假设（容量 = 一期成稿字数），而一期脚本
实际消化的是数倍原文，照旧口径折算会把期数报多、把预检拦错。项目自己定了计划期数
时以人为准，那是人的判断，照这个数排。

**这把尺只在图上用。** 写作侧「这一次调用装不装得下原文」由**输入额度**（token，
= 最大输出 × `llm.input_ratio`）判，见 3.3.2——本数透传下去只作**摊配额的换算**，
不参与「装不装得下」的判断；两个不同单位的数相减再比大小，正是技术文档那一期被判
「超出容量」的出处。倍率调大调小，地图一个字节不动；改时长改档位，倍率也不用动。

**分量有上限也有下限，都在排图那一步管。压比的分母是成稿目标（不含偏移）。**
上限 = 档位 × 1.25（素材容量 x = 1 × 1.25 × 档位）：1:5 档压到压比 6.25 仍算
达标。下限不看档位：压比低于 1.5（= 1.2 × 1.25），即原文不足偏移后脚本的
1.2 倍（25 分钟一期 ≈ 9877 字），模型就写不满——实测它与素材近乎 1:1 消耗（4034 ÷ 4132 ≈ 0.98），留两成余量才有得压；
写不满的出路只剩把写过的段落再背一遍，这一期**判不达标**。排图之前还有一道**产能预检**：
把期数与素材总量对账——每期连下限都摊不到 → 直接报错拦下，不烧一次注定失败的排图；
素材远多于期数按上限能消化的 → 警告期数偏少，不拦（按上限截断后的实际期数算）。
排完图逐期体检，不达标时把**算术化的**问题清单（哪一期、压比多少、上限多少）作为反馈
**整体重排**：凝缩结果复用，重排只是重新分组（一期塞几个凝缩），不是重新凝缩，期数在
人定/自定两态下都放开、由模型按内容重排；最多重试 2 次。收口分两极：**仍超上限报错
停下交人**（压不动的期写不出来，落库等于让后面每一期都照错的图出片），**仍低于下限
落警告放行**（料不够写出来是短、不是错，源头另有产能预检与下限两道闸门）。素材总量连
一期下限都不到时短路——直接警告，不烧重排。

**上限是排完之后的红线。** 组出来的期数超过「地图期数上限」时报错要求合并，不做
排前截断。体量折算值在三处露面：排图前的产能预检、撞红线时说事、给模型的分量提示
（**上限与下限都印进提示词**——线不告诉它，它第一轮必然踩，重排只是补救）。

**单元层级按文体判。** 「按哪一级凝缩」是凝缩的**前置**决定：选 H1 凝缩 39 次，
选 H2 就要凝缩 179 次。凭据是文体——这个类型里什么算一个完整的表达单元（范式卡的
`unit` / `probe.unit_hint` / `split`），不是标题的具体程度。`classify()` 把这些
文体判据连同各层**真正要凝缩的条数**一起递过去，并说明代价：选细一层不只多花时间，
碎片拼期比整体分组更容易拼歪。

**位置随凝缩一起落盘。** 每个单元带它在原文里的起止行（`end`）与所属章节链（`path`）；
凝缩时由 `slice_by_anchor` 实测的范围回填（`loc`）并与结构自算的对账，不一致出声。
排图清单里每条都带行号范围与所属，取料照落点切——**凝缩压的、地图上标的、脚本里
取的，必须是同一块**，否则地图看着完整，取的却是别的段落。

**组织依据来自范式。** 切分依据、整合依据、重点判据、推进方式四段，按素材类型
（方法论 / 小说 / 采访 / 论文 / 教程 / 传记 / 随笔）给不同的话。从前这里只有一句
"按素材自身的推进顺序排期"，对什么素材都是这句，等于没说。

**凝缩规则与排图判据分开写。** 范式卡里是两个字段：

| 字段 | 口径 | 谁在用 |
|---|---|---|
| `focus` | **选**：什么值得单开一期、什么并进去、什么不播 | 排图提示词（`prompt_block`） |
| `condense` | **不丢**：这一节说了什么、反对什么、有几条主线、细节区分在哪 | 只给凝缩那一步 |

从前这两件事缝在同一段里，`prompt_block` 给它的标题就叫"重点判据与凝缩规则"——
字段名自己就承认它身兼两职。一个要全、一个要挑，方向相反：一次全喂给凝缩，模型会
先按"挑"办事，该留的细节区分被当成次要信息丢掉。拆开之后 `prompt_block` 只拼前四项
（`condense` 不进排图提示词），`condense_units` 只吃 `condense`。

自定义范式卡（`register()`）没写 `condense` 时，**注册那一刻**补上通用口径
（`DEFAULT_CONDENSE`）——补在卡上，不做事后兜底：凝缩的依据要能从卡上读出来，运行时
才发现缺了再猜，等于把这道工序的标准藏进代码里，换一张卡就查不出地图为什么漂。

**落点核对前移到排图之前。** 切不出非空正文的条目在 `admissible()` 就挡掉，
不等排完图再回头清理——那时模型已经按一条空落点写过要点了。

两级之间只有「章节标题 + 行号」这一个标识，所以 `_strip_markdown()` 遇到标题行必须
原样保留：`#` 是结构锚点，剥掉它，上传 md 后再也找不到锚点，按章切分就无从谈起。
而纯文本与 docx 没有 `#` 可依，靠的是正文里的编号（`第X章`／`1.2`／`一、`／`(一)`／`a)`／
`08a`）与 Word 标题样式——编号写在正文里，抽成纯文本也还在。

**期号一律由代码编。** 模型只输出分组、标题、主旨、要点。让它编期号，一旦有一期
对不上，后面全部错位，而每期单看都正常——这类错位没有任何一处会报错。分支期号同理，
由 `assign_branch_nos()` 一处编出，界面与出片阶段都不再各写一套。

**插入与排图是同一条管线，只是容器换了。** 画地图是在空根容器里建 1、2、3……，
插入是选定锚点期做父容器，在它下面建 3a、3b……——除了容器参数，凝缩、分组、
落点、体检完全同款。所以 `plan_insert` 内部就是：新素材逐单元凝缩（`condense_units`，
已凝缩过的节直接用缓存，不重烧）、序号分组、落点由代码映射（`_episodes_of`，
模型只填 `units` 序号）、压比体检照跑（`_regroup_loop`，与排图共用同一条回线）。
插入对模型多要一个判断——新料与已有各期哪期相关——所以提示词里先给带主旨的
已有计划简报（`_plan_brief`），锚点（`anchor_no`）由模型定，其余与排图同口径。
落点不再由模型抄，旧管线「清单用「」界定标题边界、回来逐条核对」的那套
（`BRIEF_LEGEND`/`_clean_rows`）随之退役：抄不错的东西不需要核对。

**插入分两步走**：`plan_insert` 只回建议不落库，人看过、改过再 `insert_branches`。
一步到位看着省事，但插入点是模型定的，落错了要回退整张地图。

**插入面板自带入库区。** 插入的本质是「把新材料加进来」，所以上传区不放在另一个
面板里：`uploadBlock()` 与 `collectUpload()` 由成稿面板与插入面板共用，两边走同一个
`/api/source action=add`（入库即探查），入库后按 `scope` 重画对应面板。可勾选集合按
`mapSourceIds()` 分两种：已进地图的标出「已在地图中」并默认不打勾，未用过的默认勾上。

**不勾素材时默认只处理还没排进地图的。** 缺省口径取「素材集合 − 地图 refs 里
出现过的 source」：已排过的素材再插一遍等于重插——期号产出 3a、3b，内容与既有
各期重复，而这件事不报错；全部素材都已排过时直接报错，请先入库新料或改用重排。
界面上 `mapSourceIds()` 的默认勾选与此同口径。

### 4.2 管线接口

```python
run_episode(cfg, calib, material, title, episode_no="", project_dir=None,
            script=None, preset_key=None, extra="", llm=None,
            do_video=True, reuse=True, job=None, project_id="") -> dict
```

九个步骤，每步都有门禁：

```
1 脚本 → 2 资源 → 3 语音 → 3b 校准回填 → 4 音频后处理
→ 5 编码 → 6 字幕 → 7 画面 → 8 文章与清单 → 9 完成
```

脚本排在资源之前：背景与封面上要印本期标题，而标题由脚本产出。
先做图再去问标题，等于把已经定下来的东西回头再问一遍。
（画面上最大的一行不是期标题而是节目名，见 5.1；但期标题仍要印上去。）

脚本这一步之前还有一件事：**本期素材从哪来**。它由项目范式决定，判据只有
`resolve_material()` 一处：成稿规划的料源是地图落点，调用方递来的素材一律不作数
（忽略时记一条日志），按本期在地图里的 `refs` 取回**涵盖单元的原文**（`compose`，
含子节、不截断——一期的体量在排图那一步已按目标时长定过）；逐期即兴、单集与未定
模式的料源由调用方给（三者都不排图，判据是同一条，不另开分支）。缺地图、缺落点、期号不在图里，都在取料之前拒绝——不留"先拿空素材
让模型硬写"的出口。生成脚本的 HTTP 接口与出片阶段调同一个函数：各写一份的话，
迟早有一处先漂，而漂出来的产物表面上完全正常。

成稿规划没排图时根本进不了这一步：「设为当前」置灰，脚本页与合成页的下拉都不列它。
拦在入口而不是拦在生成时——到了生成时才说"缺前置"，人已经白走一趟。

本期的主旨（地图片段 `gist`）与取材单元一并进系统提示词，落在「本期计划」那一段里：
这一期为什么被划出来、该讲什么，在排图那一步已经定过，写的时候不必让模型再从素材里
猜一遍主题。

返回 `{project_dir, assets, estimate, timeline, measured_seconds, audio_duration, report, project_id, next_episode, …}`。
只有门禁通过的片子才记入项目并推进期号——未通过的片子不占号。

```python
continue_episode(cfg, calib, root, no, llm=None, job=None) -> dict
```

`root` 是**树根**（项目目录，或任何一棵产物树），`no` 是期号——产物按类归位之后，
一期由这两者合起来才定得下来，光有目录名不够。命令行没给期号时从锁文件反推，
但只有恰好一期卡在门禁上才自动定，零期或多期一律把选择权交回去：猜错了就是
拿着另一期的产物当这一期的接着做，而这种错在产物上看不出来。

`job["result"]` 里。进度是真的：凝缩 i/N、探查 i/N 由下层函数经 `progress` 回调上报
（`plan_map` 用 `_span` 把各阶段的局部进度映射到全局区间），不画匀速假进度条。
同一项目还有一个**互斥闸**（`pipeline.running_for`）：探查与排图写的是同一批
`<sid>.probe.json`，并行跑会互相踩——起任务前查一把，撞了就拒绝并说清原因；
别的项目不受牵连。

`frame` 是唯一一班不按前缀归的：`subtitle.font_family` 的 section 被改判到
`frame`（见 `SECTION_OF_OVERRIDE`），与 `frame.font_family` 并到同一张卡。
这两款字体管的是两处不同的地方，人挑的时候却在比字形——分在两张卡就得到两个
地方各看一遍。两款字体在界面上都由**自绘下拉**渲染：原生 `<select>` 的选项不
接受自定义字体，浏览器直接忽略选项上的 `font-family`，整列字长得一模一样，
选字体就成了盲选。候选项按各自字形渲染同一句样本，装没装的照样都列（没装的
暗显不可选）。随包字体走 `/api/fontfile` 取回文件注册成临时 font-face；系统
字体浏览器按族名就拿得到，不必再下一份几十兆的文件。

分区归属与 `group`（脚本/门禁/声音/画面/系统）是两个维度：`group` 说明这个量属于
哪一类，`section` 说明它摆在界面的哪张卡上。`project.output_dir` 的 group 是 `system`，
section 是 `project`——它是系统级设置，但该跟品牌行放在一起。

**节目名、副标题与受众都不在这张表里**，它们是项目设定（每个节目一套，跟着项目走），
出片时由 `project_store.apply_to_config` 叠成 `project.program_name` /
`project.subtitle` / `project.audience` 三个通道键送下去。改的地方是项目卡片上的
「节目名 / 副标题 / 受众」（`editIdentity`），不是设置页；不归属任何项目时三个键取到空，
画面就不印那两行（界面上已不产生这种请求——单集也是一个项目）。
期标题同样不在表里：成稿规划一律取自期数地图对应那一期，人不用填第二遍。

**受众是节目级的一句话，不是期级。** 它印在每一期片头里（「欢迎收听《X》，面向___的听众」），
所以同一档节目各期必须逐字一致——每期各生成一次必然漂移，那就不是节目的标识了。取值路径只有
一条：**画地图时问模型一次**（`MAP_SCHEMA` 里与 `episodes` 同级的必填项）→ 落进项目 →
界面上可改。三条纪律：模型只给第一版（重排地图不覆盖）、**人填过一律不覆盖**（与 `planned_episodes`
同一条纪律：人定的量以人为准）、没有地图的项目（单集、逐期即兴）留空——留空就整段消失，
片头退化成「欢迎收听《X》。」，不出现「面向的听众」这种半句。

三者在画面上的地位：**节目名是主标题（最大的一行），副标题次之，期标题再次**
（见 3.3 的层级不变式）。`cover.preset` 的三个档位排出三种样子：`book` 品牌主导（默认）、
`episode` 把副标题换到 `episode` 那一档字号、`minimal` 不印品牌行与两条分隔线；
**「节目名最大」这条不因档位改变**。

期标题与期数都归背景——封面跟项目、不跟期，这两行不进封面（清单见 3.1）。期标题退出
封面之后，`episode` 档剩下的效果就是副标题换一档字号；三个档位仍排出三种样子，有测试
比对形状守着。

配置项必须全部有实际读取点。定义了却无人读取的键会在扫描中暴露并移除——
表里的空位比缺功能更容易误导人。

### 5.2 时长模型

```
语音秒数 = 有效字数 / (k · 语速)
有效字数 = 汉字 + 0.5 × 标点 + 1.5 × 西文词
```

- L1：单参数 `k`，由实测反推
- L2：三参数最小二乘 `t = a·hanzi + b·punct + c·latin`，样本 ≥ 20 时启用，矩阵奇异则保持 L1
- EMA：`k ← 0.3·k_new + 0.7·k_old`，单集异常不带偏系数
- 分组键：`(引擎, 音色, 语速)`，不同组合各自记录

#### 5.2.1 时间轴的实测校正

字幕时间轴不是纸上推导，而是**以最终音频实测时长为准**做线性校正：

```
推导终点 = 片头偏移 + Σ(逐句实测) + 停顿 × (句数 − 1)
正文终点 = 最终音频时长 − 片尾时长
缩放系数 = 正文终点 / 推导终点      # 偏差 ≤ 0.25 秒时不校正
```

片头与片尾时长由拼接层向上返回。把这两个数藏在拼接层里，等于让字幕整条错位且外部无从察觉。

### 5.3 门禁级别

| 级别 | 数量 | 不过时 |
|------|------|--------|
| fail | 16 | 写锁文件留痕；产物落了盘就出片、就记账，过没过写进报告 |
| warn | 4 | 严格模式下同样判不过（同上：留痕 + 出片 + 记账） |

其中 `check_semantic` 为 fail、`check_promise` 为 warn，两项都是**模型判断**，
但判定结果分三态：**判为不通过**的照常参与放行——这正是它们拦得住人的原因；
**模型没给出结论**的记为「未判定」，带 `advisory` 标记落进 `pending` 交人工。
模型的不确定不该被当成硬事实，可「没检查」也绝不能当成「检查通过」。

判定分流只有一条规则：

| 集合 | 条件 | 是否影响放行 |
|------|------|--------------|
| `fails` | 非 advisory 且不过且级别为 fail | 是 |
| `warns` | 非 advisory 且不过且级别为 warn | 严格模式下是 |
| `pending` | advisory 且不过 | 否 |

放行结果 = 无 `fails`，且（非严格模式 或 无 `warns`）。`pending` 不参与。

**未判定也要留痕。** 模型不可用、调用异常、输出无法解析、或者干脆漏返回某一项时，
这些项仍要出现在报告里，状态记为未判定并计入 `pending`。静默消失会让「全部通过」
变成假象——摘要上的待复核计数就是模型侧待人工过目的工作量。
**缺键绝不默认通过**：那等于把「模型偷懒」记成「检查通过」。

承诺链检交给模型而不留在代码里，是因为词汇匹配判不了「那个口子收没收」：
对话体一问一答本就用词不同，前后不重现同一个词恰恰是正常的样子，
拿重叠率去判会把正常脚本判成断档。这属于 09c 说的语义免疫——
语义判断要用推理范式，不能用匹配范式。判据是「那件事有没有被回答」，不是「字面有没有重现」。

两段各自成环，但内容检内部仍是**一次调用判完**：语义检与承诺链检读的是同一篇脚本，
分两次就是把上下文喂两遍，白花一次调用，还多出一次两次结论不一致的机会。
**语义检是配置开关、默认关**（`script.check_semantic`）：它要逐句核素材，素材装不下
还要分批，最坏八次调用，是全链最贵的一项。关掉时只判承诺链检——它**不看素材**、
只看脚本自己开的那个口子收没收，因此不再分批，稳定一次调用判完；开着才按原文切批。
承诺链检**必检，没有开关**。

审校的输出必须带落点，且**两块问题的形状不一样**：语义项是 `{line, quote, problem}`
（哪一句、那一句里的原话、毛病是什么）；承诺项是 `{line, promise, how, speaker, close_after}`
（承诺提在哪一句、承诺是什么、怎样才算闭合、这句闭合的话由谁来说、建议插在第几句之后）。
**这是定点修补的前置条件**：检查只说「整篇偏题」而不说哪一句，补丁就无处可下。

**落点不许是 0。** 契约把 `line` 收紧为「≥1 且不超过总句数」（约束解码实测吃
`minimum`/`maximum` 两个硬约束），提示词也不再教模型「找不出具体哪一句时填 0」，
而要求它填**其中最该改的那一句**。模型仍给不出有效句号时，程序**拿问题自带的 `quote`
去稿子反查**（去空白后比对子串，不花模型调用）；反查不到就记一笔「未修好」，
**不早退、不重写**，其余项照修。不拿「最接近的一句」顶替——填了假句号，改稿的人会去改
一句没毛病的台词，真正的问题原封不动，下一轮又原样报一遍。

**承诺项的修法是插入，不是改写。** 要补的是「后文那句回应」，而它现在压根不存在——
所以补丁新增 `inserts` 形态：在 `close_after` 锚定的那一句之后**插一句新的**（带说话人），
与既有的 `absorb`（并句减行）并存。旧契约只许改被点名的句子、不许增行，结构上做不到这
件事，逼得模型去删承诺句——问题在报告上消失、稿子一字未动。提示词同时写死三条：
语义闭合（`how` 要具体到该回应哪一件事，不许写空话）、角色闭合（`speaker` 必须给 A 或 B，
不许只给一句没有说话人的话）、不许删承诺。

审校调用的输出预算与探查、写作同一条口径，取全局 `llm.max_tokens`，不另写一个小值：
推理型模型把思考过程也算进 max_tokens，预算给小了，思考吃完就没有答案，
两项检查会一同落空，报告上只留两行未判定。遇到「上下文超限」这类后端拒绝，
是模型实际加载的上下文小于该预算，调整的是加载参数或该预算本身。

**这条口径适用于每一次调用，没有例外**；对配置值做夹取（`min(..., N)` 之类）同样算「另写
一个小值」，换个方向而已。规划轮曾按「一份规划不需要 4 万 token」把自己夹到 4096，配置里
的 47872 到不了后端，思考段先吃光那 4096，规划轮以「模型返回空答案」收场——现象看着像模型
不听话，起因是预算在调用处被改了。**嫌某次输出长，该动的是 `maxItems` 与字数核账，不是
预算这一层。** 代码级约束见 `test_every_call_uses_config_budget`（哨兵值跑通全程）与
`test_no_call_clamps_the_budget_in_source`（扫源码拦夹取）。

位置放在脚本生成里，不在产物之后：检出不通过就带着**检出的落点**去定点修补，
脚本还改得动的时候才拦得住；等音频视频都渲染完再检，片子已经定死，检出来也改不动。

**脚本生成是三段串行、后两段各自成环的。** 顺序（v0.36.0）是**出货 → 检查 → 门禁**：

1. **出货段**只求一份**可用稿子**——内容对不对、形式合不合规都不判。产物不可用（输出拆不开、
   一句可用内容都没有）在本段重试，次数吃 `script.segment_parse_rounds`（与段级解析重试
   **共用**这一个数，不另起一个）；用尽就报错，不往下走。
2. **检查段**跑内容检（模型判）：修到过、或修满 `script.check_rounds` 都往下走——内容没过
   不等于稿子不能用。首轮不出货，直接核出货段留下的那一版。
3. **门禁段**跑形式门禁（代码判）：修到过、或修满 `script.gate_rounds` 就落盘定稿。
   **修满仍不过不在这里空转**，带着问题交人。

三段各用各的预算，互不侵占。门禁排在最后不是习惯问题：它每轮**重新判形式**，再把这之前
内容检的结论并回报告——形式结论因此永远对着最终稿。反过来的排法（门禁在前）里，中间检查段的
补丁会插入新句（加行，可能冒出连说超限），改完没人复核形式，报告上留着旧稿的结论——
「报告绿、稿子坏」的静默放行就是这么来的。

**这三段内部没有重写。** 对一份可用稿子，它们只有「判」与「定点修」两种动作；重写只属于
正文生成步骤——第一次写，或产物不可用（解析不出稿子）时重试。补丁落不了地也不重写，改为
**下一轮重发同一批补丁**（输入一模一样，一次定点调用远比重摇两百句划算），用完仍落不了地
就保留这一版原稿。补丁里**单条不合格只拒该条**（越界、没点名、空文本、并句三条硬校验），
其余照落；被拒的原因随下一轮提示词一并递回去（`【上一轮为什么没落地】`）。条目骨架不成形
（不是对象、句号不是整数）才整份退。

**并句的字数判据是一个恒非空的区间，判据与处方同源（v0.37.0）。** 从前判据是
「并后 ≥ 原句合计 × 70%」，提示词又硬性要求「每句 ≤ 40 字」——原句合计 > 57 字时两条同时
满足是不可能的（**数学无解**），而 70% 这条一个字都没进提示词，模型只会按「合并＝精简」写。
真机上并句因此一次没成功过（当时本机 A 捧哏上限 1 句，「并成 1 句」正是最易无解的情形；v0.38.0 起放宽为 2）。
现在唯一的算处是 `absorb_span`，返回 `(lo, hi)`：常规区间 `[单句上限 × 70%, 单句上限]`
（本机 **28~40**）；原句合计连 28 都不到时退成 `[原句合计 × 70%, 原句合计]`；再抬到不低于
单句下限（`gate.min_chars`）。**区间恒非空，上限必然 ≤ 单句上限**——并出来的句子不会再被句长
门禁打回。判据（`apply_patch`）与处方（`patch_targets` 的并句分支）**调同一个函数**，处方里
直接写给模型「每句 %d~%d 字」，不许两处各算一遍。


同理，语义检的判据范围就是呈上去的整份稿子：片头语与片尾语**不在这份稿子里**（要到整期定稿
那一刻才由 `glue_intro_outro` 粘上），素材里没有它们当然不是缺陷，也就不必再为它们单开一条
豁免。判据范围与结构要求冲突时，错的是判据。

这不是放水，是划界：**模型没给出结论的**留给人工；模型判了不通过的，照拦。

### 5.4 项目一棵树

立项就是建这棵树。此后每一阶段的产物都落在自己的子目录里，不再有一个「集目录」
把一期的所有东西混装在一起：

```
<产物根>/                       # project.output_dir，默认 projects/
  _projects.json               # 登记表：只存身份与设定，不含地图
  20260912-121051/             # 项目目录，目录名即项目 id
    素材/  index.json  s1.md  s1.probe.json
    地图/  map.json
    脚本/  1.json  2.json  …
    封面/  1_cover_16x9.png  …
    背景/  1_bg.png  1_bg_v.png  1_bgm.wav
    音视频/ 1.mp3  1.mp4  1_v.mp4
    字幕/  1.srt  1.lrc
    图文/  1.md
    报告/  1.manifest.json  1.report.json
    过程/  1/            # 中间件、锁、被拒件；本期跑完即无用
```

十个子目录在立项那一刻一次建齐——空目录也是承诺：使用者看得见「这一期还差什么」，
而缺目录只能靠猜。

**路径只有一个来源。** 全部由 `layout` 拼，业务代码不自己拼字符串。`layout` 的函数
收「树根」而不是 `(base, pid)`，所以不归属任何项目的产物也能复用同一套布局，不必为
它另写一份（`single` 收编之前，单集走的正是这条不归属的路径）。

**各阶段各自落盘。** 素材入库即落、地图排完即落、脚本生成即落、出片产物各自归位。
早先脚本只活在浏览器内存里，出片时才第一次写盘——于是「先生成、改一改、再合成」这条
路根本走不通，脚本与合成被绑成了一步。落盘之后这两步才真的是两步。

**一份材料只有一个落点。** 产物按类归位（背景在 `背景/`，字幕在 `字幕/`），不按
「一期一目录」摊开。同一期的背景图与音频分居两处看着别扭，但它换来的是「全项目的
背景图在哪儿」这个问题有唯一答案——按类取用（换字体重排、批量替换封面）才不必
逐期翻目录。

```
<项目>/报告/<期号>.manifest.json  清单
<项目>/报告/<期号>.report.json    逐项门禁结果
<项目>/过程/<期号>/               中间件、脚本阶段门禁结论、LOCK.json（仅产物门禁不过时）
```

文件名前缀一律是 `layout.safe_no(期号)`，所以分支期号（`3a`）也不会与主期撞名。

`manifest.json` 记录配置快照、资源路径、实测时长、断词率、字体来源与校验摘要。
`report.json` 是逐项门禁的完整结果，每项都带实测值与判据，并含 `fails` / `warns` / `pending` 三个分流集合。
它只装**产物阶段**那 8 条：脚本阶段的结论在 `过程/<期号>/gate.generate.json`（见 3.6），
两阶段的账不混进同一份报告。
人带着脚本阶段的未通过项出片时，清单里另存一个 `script_issues_ack`（时间 + 未通过项标签）作凭证。

清单只写**实测值**，不写估计值。写不出实测的项就不写，不留占位。

## 附：改动自检

改代码前问八句：

1. 这个量在别处是不是已经有一个来源了？
2. 这一步是确定性的吗？是的话为什么在调模型？
3. 参数不可达时，是报错还是悄悄降级？
4. 新加的可调项进表了吗，还是散在业务代码里？
5. 这个量是人定的还是模型拟的？人定过的，代码要持有它，别让模型回填覆盖。
6. 这一步在要什么，实际又在验什么？门禁只要求被要求的东西。
7. 同一条规则是不是在几处各写了一遍？期号怎么编、模式能不能改这种规则，
   前后端各写一套，漂掉的那一处不会报错，只会悄悄编出错位。
8. 要求模型输出的每一个字段，约束解码的 schema 里都有位置吗？
   用错 schema 的症状是「模型答不出来」，而不是「模型答错了」——
   换个 schema 输出就变了，这两件事必须一起看。

八句都过，再提交。
